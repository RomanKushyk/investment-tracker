# @quirenote/core — the pure domain layer

The domain layer the app and `infra/` both import (*Core is pure*). A workspace package consumed
from source: its `exports` point at `.ts`, there is no build step and no `tsconfig.json` of its
own, so the SPA's compiler options and the backend's each compile these same files. `infra/` pulls
in only what it imports rather than the whole package — measured with `--listFiles`, never counted
by hand.

Consolidated in next-phase Phase 1 from v1's `src/lib/{types,derive,format,colors,asset-builder,schemas}` plus `src/screens/shared/` (now dissolved). The v1 pinned contracts keep their exact shapes — only module paths changed.

## Layout

| Module | Responsibility |
|--------|----------------|
| `types.ts` | Domain types (`Asset`, `Snapshot`, `Transaction`, …) — v1 pinned contracts, moved verbatim; plus `QuoteOrigin`/`QuoteSource`, the provenance of an unsaved quote DRAFT (P3 D20 — stored in `state/draft.ts`, never in a Dexie row) |
| `derive.ts` | Every displayed figure derives from these (D5 reconciliation rules); `headlineKpis` is the sidebar's single KPI source |
| `money.ts` | Number/currency/date formatting (README §8) + **the one signing helper** `signed()` — U+2212 minus everywhere (D8) |
| `dates.ts` | Pure ISO date math: `todayIso` (single source, was triplicated), `daysBetween`, `latestSnapshotDate`, `addMonths` (month-end clamped) + the Europe/Kyiv helpers `kyivDateIso` / `kyivTimeHm` / `msUntilNextKyivHour` (offset always read from `Intl`, never a hardcoded +2/+3 — D19) |
| `colors.ts` | Chart paint as `var(--color-chart-*)` strings (aliases resolve in `src/index.css` `@theme`); `COLOR_KEYS` cycle for new assets |
| `asset-builder.ts` | `buildNewAsset` (quick-create pinned rules) + the P2 AssetForm mappers `assetFromForm` (create) / `assetPatchFromForm` (edit patch; hidden fixed-coupon fields are never touched, visible emptied ones clear via explicit `undefined`) |
| `schemas.ts` | zod form schemas, every one a FACTORY OVER THE LANGUAGE (D87 — a lone comma is the decimal in Ukrainian and grouping in English, and `groupsWithCommaFor` is the only place that rule is written): `amountInputSchema(lang)` and `percentInputSchemaFor(lang)` for the fields that live outside a form, `assetFormSchema(mode, lang)` (all editable Asset fields incl. the `inzhur {kind, ref}` group — **no `units` since D117**, no `couponAmount` since D119 which replaced it with `couponRatePct` bounded (0, 100]; `'none'` schedule accepted in edit mode only), `transactionSchema(lang)` — schemas emit paths, never English (D8) |
| `xirr.ts` | Money-weighted annualized return (Newton–Raphson + bisection fallback) per the P1 formula audit (D13, `docs/reference/FORMULA-AUDIT.md` §6.1) |
| `backup/` | `json.ts` — the backup envelope (`quirenote-backup`, `formatVersion` 8) serializer + zod validator (D12); the format/version gate `readEnvelopeHead`, the row schemas and the structured `integrityIssues`/`RowIssue` vocabulary are shared with the importer. `import.ts` (P4 D24) — `classifyImportFiles` (the four S2 file gates), `validateImport` (format dispatch → row schemas → referential integrity, all as structured issues) and `diffBackup` (per-table added/replaced/removed + the six warning tokens the S3 dialog lists). **It extends `json.ts`, never forks it**, and it writes nothing: the caller reads the file, the Confirm press does the write |
| `ovdp.ts` | The OVDP coupon convention, and a LEAF on purpose: `PAYMENTS_PER_YEAR` (payments per year by schedule, 0 = pays none) + `OVDP_FACE_UAH` (1000 — measured, all 32 live bonds, `docs/reference/OVDP-COUPON-STRUCTURE.md`). Both were declared in `accrual.ts` and are still re-exported from it, so every existing citation holds. They moved because `inzhur/parse.ts` needs them for D119's rate derivation and `infra/tsconfig.json` compiles `parse.ts` — importing `accrual.ts` there dragged `derive.ts`, `period.ts` and `xirr.ts` into the backend's typecheck, and `derive.ts` is edited constantly. Imports nothing but `PayoutSchedule`, which is what keeps `derive.ts`, `period.ts` and `xirr.ts` out of the backend's program — measured with `--listFiles`, never counted by hand |
| `accrual.ts` | Fixed-yield automation (P3 D21): `couponPerPayment` (₴ ONE payment pays — `rate/100 ÷ perYear × 1000 × units` since D119, gated on `yieldType`, ledger count then the link's legacy total, `undefined` for a closed position; every coupon figure in the app routes through it), `dailyAccrual` (stated coupon ÷ period, else the `expectedPct × invested` fallback — ACT/365), `couponsInGap` (a coupon paid in the gap DROPS the price), `suggestedQuote` (S4's ghost carry-forward, clamped at maturity), `couponRecorded` (the ONE ±7-day dedupe predicate), `nextUnsettledCouponDate` / `nextUnsettledCoupon` (the grid walk past recorded/skipped occurrences, with and without the ₴ figure — the date-only form exists because `scheduledCouponMonths` was paying for a ledger walk per asset to build an amount it discarded — the ONE coupon-occurrence source, shared by `dueCoupons` and `reminders`, D23), `dueCoupons` (S5), `rollNextCoupon` (clamps onto `maturity`, then flags `matured`; takes the occurrence to roll off), `couponProjection` (the Overview/Seasonality projection incl. user-created bonds), `couponReminderId` (the derived id the S5 skip and the S6 reminders share) |
| `reminders.ts` | Serverless reminders (P3 D22/D23): `computeReminders` (coupon kinds read `accrual.nextUnsettledCouponDate` — the walk WITHOUT the ₴ figure, which it never uses, so a settled occurrence hands over to the next one) → the pinned `Reminder[]` contract (four kinds with DERIVED ids — `quote-missing:<date>`, `coupon:…`, `coupon-overdue:…`, `maturity:…` — severity tokens, ordered overdue → warn → info, dismissals filtered), the id builders, `DEFAULT_LEAD_DAYS`/`MATURITY_LEAD_DAYS` and `isLeadDays` (the one 1–30 validity rule, shared by the S8 field and the persist sanitizer). Derive-don't-schedule: nothing is stored, so dismissals expire with their occurrence |
| `inzhur/` | `parse.ts` — tolerant pick-parse of the public feed (unknown fields ignored, per-entry skip), `kopecksToUah` (the ONE ₴ conversion), `positionValue`, `nextPaymentOnOrAfter`/`couponForecast`, `matchAssets` (slug/ISIN, trimmed + case-insensitive), the feed `title` for the S7 picker rows — policy in D19; `__fixtures__/assets-sample.json` (trimmed live capture of `GET https://www.inzhur.reit/_api/assets`, 2026-07-28) is the test basis and `__fixtures__/assets-2026-09-23.json` (that day's active bonds) the final-period witness for `dcf.ts`, `scheduleFacts` (maturity + next coupon + cadence + coupon rate off one feed entry, D121), `sameRef` (THE one answer to "do these two links name the same instrument" — three copies of the rule existed) and `NO_UNITS` (the frozen empty units record, `Object.create(null)`). `offer-page.ts` — the offer page (`/offer/ovdp`) the capture reads since the feed is refused, reshaped into the feed's entries so `parseAssetsFeed` reads both: the devalue-encoded catalogue, the schedules from an island's props, and `FUND_SLUGS` (the feed's own id/slug pairs); `__fixtures__/offer-ovdp-2026-09-24.html` and `__fixtures__/assets-2026-09-24.json` pin it to the last feed capture. `ref.ts` — a LEAF with no imports holding `normalizeRef` and `sameInstrument`, because four call sites across three layers compare the same string and every private copy of the rule has been a bug (`sameInstrument` deliberately ignores the KIND; `matchKey` deliberately includes it) |
| `address.ts` | The one rule for an address this system will store — ASCII only, so the fold done in TypeScript and `app_user_email_lower_ck` on the cluster are the same operation. Here rather than in `infra/` because the sign-in screen checks the same pattern before the relay does; two copies would be two answers to what the cluster accepts |
| `seed.ts` | The reference dataset — pure data builders, no db access (*Derived figures and the seed*). `src/lib/repository.ts` is what writes it; the rows themselves are domain, and the view-model tests below are built on them |
| `view/` | The eight per-screen view models — `allocation`, `attributes`, `balances`, `overview`, `payouts`, `portfolio`, `seasonality`, `yield` — each returning typed rows for one route, and together the union `/view` will serve. They import core and nothing else; two of them are read by a screen other than their own (`Overview` reads `view/yield`, `Payouts` reads `view/overview`), so the surface is not one module per screen |

## Rules

- **Pure only** — the package imports nothing but itself (no react, no dexie, no zustand, no `src/lib`, no UI layers, and no climbing out into `src/` or `infra/`). Machine-enforced by the ESLint `no-restricted-imports` zone in `eslint.config.js`, and that zone is itself held: it is keyed to this directory, so `src/domain-purity.test.ts` lints text at a path in here rather than reading the config, because a selector that stops matching parses perfectly green.
- **Structured returns** — the domain modules and the `view/` ones return keys/tokens (`{schedule, day}`, ISO dates, plain numbers), never assembled English prose; the component layer owns the words (e.g. `components/ui/date-labels.ts`, `components/ui/schedule-labels.ts`). i18n lands in Phase 5.
- **One sign convention** — every signed display string routes through `money.signed()`: U+2212, never ASCII `-`.
- Every module with logic ships a colocated `*.test.ts` (vitest, node env). Exceptions: `types.ts` (type-only) and `colors.ts` (static token-string tables, exercised through their chart consumers). The seam test between `types.ts` and `infra/schema/user.ts` is `infra/src/model-parity.test.ts`, deliberately on that side: it has to cross the boundary the "Pure only" rule stops at, and a test that crossed it from in here would make the package depend on the backend that depends on the package.
