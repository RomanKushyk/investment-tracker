# Quirenote — Investment Portfolio Tracker

Read README.md first — it is the full implementation spec (design tokens, screens, data model, behavior checklist).

## Key facts
- Design reference: `design/Investment Tracker.dc.html`. All styles are INLINE in its markup — read it for any exact color/size/spacing. Ignore `design/support.js` and `_ds/` references (prototype runtime only).
- Stack: React 19 + Vite + TypeScript + Tailwind 4 (see package.json). pnpm.
- Fonts: **IBM Plex Sans** (headings/buttons/KPI numbers) + **JetBrains Mono** (body) — via @fontsource. They replaced Space Grotesk + Spline Sans Mono on 2026-08-12 because **neither of those carries a single Cyrillic letter** and Ukrainian is now the default language (D54). The design reference still shows the old pair; that divergence is deliberate. JetBrains Mono keeps the same 0.6em advance, so no width in the reference moves.
- All portfolio figures must be DERIVED from stored data (snapshots, transactions, assets) — never hard-coded. Seed with the mock data from README §7 so first run matches the reference.
- Persistence **today**: **Dexie.js on IndexedDB** (db `quirenote`) behind `src/lib/repository.ts` — D2. The app is still entirely local; nothing in `src/` talks to a server.
- **Backend alerting has NO SNS topic, and that is deliberate** — the alarms in `infra/template.yaml` carry no `AlarmActions`. CloudWatch publishes alarm state changes to EventBridge for every alarm regardless, and delivery is EventBridge → AWS User Notifications → the Console Mobile App. Email was abandoned after three subscriptions died within seconds of confirmation (D44, D45, D47). Do not "fix" this by adding a topic back.
- **There is now a backend, and the app does not use it yet** — `infra/` runs a daily job that archives asset prices into Aurora DSQL (see `infra/README.md`). It exists to capture what nothing else records, and **D72 narrowed what that is**: the Inzhur DEALER QUOTE for every instrument, which exists nowhere else and starts 2026-08-11, plus fund prices after June 2026 until Inzhur's client API ships. It is NOT the only history there is — the funds have Excel files on the site through June 2026, and bond history at NBU fair value is **already in the archive** from each bond's issuance. Those are different bases and must never be merged (~0.9% same-day divergence, D26/D27). The planned move of the app itself onto it is in `docs/superpowers/specs/2026-08-04-cloud-stack-and-cost.md` and `-data-model.md`. Do not assume either state — check which layer a task is about.
- **Shape is a system, not a taste (D56)** — nothing in the app is a capsule. A standalone control takes `round(min(w,h) × 0.26)`; a box nested against a parent's corner takes `outer = inner + gap`; a segmented control is both (segment proportional, track concentric). Surfaces keep the reference's 16/20/24. Only the logo circle, asset avatars, colour dots and the decorative blob stay round. Measure the RENDERED height — `text-[11px]` sets no line height. Full rule in README §4.
- **Nothing scrolls with the platform's bar (D65)** — every constrained box goes through `src/components/ui/Scroller.tsx`. Rail 12px = `2+2+4+2+2`, thumb r1, rail r5. **Margin 8, equal on all four sides, gutter `2m + 12` = 28 — one number, every surface, every width** (the `R − r` / `R − 2r` concentric insets were tried and dropped: invisible on a shape this thin, and 40px a side was real estate). `Math.max(8, ceil(R × (1 − 1/√2)))` guards a corner rounder than R 27. **The gutter is the ScrollArea ROOT's padding, both inline sides, fixed** — padding on the viewport is inside the scroll box and slides away under the rail. Pass `orientation="both"` for content you did not author: the axis you omit is `overflow: hidden`, not merely unscrollable. A scrolling band needs `min-h-0` AND `min-w-0`. Dialogs are three bands (`DialogHeader`/`DialogBody`/`DialogFooter`) in a grid — only the middle one scrolls. `Select` keeps the styled native bar (Radix owns its viewport).
- **The app has TWO SHELLS and one breakpoint — `md`, 768px (D66)**. Below it the sidebar is an off-canvas 280px drawer (a Radix `Dialog`, so focus trap / Escape / scroll lock / focus return are the library's) and `src/app/AppHeader.tsx` carries the capital; at and above it, the 244px rail in flow plus a collapse control that hands the header the same job. The old 136px `max-sm:` rail is **retired** — a `max-sm:` override in the shell is a regression. The breakpoint is written twice, as `max-md:`/`md:` and as a literal in `src/hooks/useIsDesktop.ts`; keep them equal. **44 × 44 is hit area, never geometry**: `src/components/ui/tap-target.ts` grows the pressable region and leaves every radius where D56 put it — only the quote input and `Button` size `md` are allowed to grow, and a text field can never take the overlay (an `<input>` renders no pseudo-element).
- **The logo is mark 04** — four bars, height is value and opacity is age. It lives in **three** places that must change together — `src/app/Sidebar.tsx` (`Mark`), `public/favicon.svg`, and `public/apple-touch-icon.png`. The first two are pinned against each other by `src/app/mark.test.ts`; the PNG has no automatic guard (a raster cannot be diffed against an SVG in vitest) and is regenerated with `node scripts/build-touch-icon.mjs`. Bar centres are EVEN — a bar spans `[x-2, x+2]`, which only halves to whole device pixels at 16px when `x` is even. The sidebar circle no longer carries ₴/$.
- Currency toggle (₴/$, rate 44.83) converts display of headline KPIs + sidebar only; tables stay in ₴.
- Number format: tables use `68 702,10` (space thousands, comma decimals); prose/KPIs use `₴68,629.36`; dates `dd.MM.yyyy`.

Bodies move VERBATIM, IDs never change, and a task closes by MOVING to `docs/archive/plan-a|b|c/` — ledger row and all — not by being ticked in place. `docs/plans/README.md` carries the folder's local rules.

## Git conventions (this repo)
- Personal pet project — **no Jira, never ask for a ticket key**.
- **Two long-lived branches (2026-08-14).** `dev` is the integration base — feature branches `<type>/<kebab-title>` (e.g. `feat/daily-quotes`) branch from it, plain conventional commits, squash-merge back into it, and every push deploys to **dev.quirenote.com**. `main` is **production** — **quirenote.com** — and moves only by merging `dev` into it, **by fast-forward, when a new stable version is cut (MAJOR, MINOR or PATCH) or on demand** (D67, superseding D59's "at most weekly"). Never branch a feature off `main`, and never push straight to it.
- **A BRANCH ALWAYS — there is no diff small enough to skip it (D73).** Every change reaches `dev` on a `<type>/<kebab-title>` branch and arrives by squash-merge: a one-line comment fix, a ticked checkbox, a typo and the `chore: bump version to X.Y.Z` commit included. The only commits authored on `dev` itself are those squash-merges. The rule has no size threshold on purpose — "small enough to commit direct" is a judgement made by whoever is at the keyboard, and it drifts one commit at a time. No PR is required (one-user project); the branch is the unit of revert and of self-review, and on a force-push-protected branch it is the only place a change can still be rewritten.
- **CODE REVIEW BEFORE EVERY MERGE, no exemptions (D76).** `/code-review` runs on the branch before it is squash-merged into `dev`; findings are fixed, or declined in writing with the reason, and only then does the merge happen. Run it at the point you would otherwise say "ready to merge", so the owner's go-ahead lands on already-reviewed work. **Documentation is reviewed too, and that is the point** — this repo's Markdown carries measured figures, pinned contracts and instructions that no test can check, which is where D76's evidence came from. Findings that are declined go in the squash-merge commit body with the reason; there is no PR to hold them. It does not replace `pnpm lint && pnpm typecheck && pnpm test && pnpm format:check`, and they do not replace it.
- Remote: `origin` → `git@github-personal:RomanKushyk/investment-tracker.git` (personal GitHub account). Push `dev` after merging; push `main` only when promoting a release.
- **No merge commits — ever.** Integrate by **rebase** or **squash** only, and promote `dev` into `main` by fast-forward. Enforced, not merely agreed: merge commits are disabled at the repo level and a ruleset requires linear history on both long-lived branches. **Rebase stays enabled and that is deliberate (D107)** — the rule is about merge COMMITS, not about rebasing. Squash is the convention for how a change arrives (D73), and it is a convention, not a setting.
- **`main` and `dev` are protected** by the `protect-long-lived-branches` ruleset — no deletion, no force push, linear history — **with no bypass actors, so it binds the owner too**. A history rewrite means editing the ruleset first, on purpose.
- **Every `gh` command here runs with `GH_CONFIG_DIR="$HOME/.quirenote/gh-config"`, and `gh auth switch` is FORBIDDEN.** Two accounts share the keyring and the owner works in two repositories at once under both, so the global default legitimately moves — `gh auth switch` would change it and yank the account out from under the other repository's session. The project config pins `RomanKushyk` regardless of what the default is doing; `~/.gh-work` does the same for the work account. It contains no secrets: tokens stay in the Windows Credential Manager keyed by host + user, and `hosts.yml` only names the active account. **What this protects:** `gh workflow run` stamps `triggering_actor` on the Actions run, so a manual deploy fired under the work account is signed with the work identity, permanently, on a public repo. The work account is NOT read-only here — measured 2026-08-18 it has `push: true` — so nothing fails loudly to warn you. `git push` is unaffected either way: it goes over the `github-personal` SSH alias.
- **Dependabot is on for SECURITY only (D104).** Alerts plus automated security fixes as repo settings, **no `.github/dependabot.yml` (nor `.yaml`)** — *that* file is what turns the dependency tree into routine version PRs, and **every merge here costs a `/code-review` (D76), so version churn would tax the gate that protects the app for no security gain.** Its absence is enforced by `src/dependabot-config.test.ts`, because GitHub's UI commits it when someone switches version updates on. **The ALERT is the unit, not the PR** — Dependabot cannot always raise one, so draining the PR list is not draining the advisories. **A `dependabot/…` branch is D73's one naming exception** (D104 amends D73): the exception is the NAME, never the gate. **And it is merged LOCALLY, never with `gh pr merge` (D110)** — GitHub's squash preserves the PR author, so the button lands a `dependabot[bot]`-authored commit on `dev`; `Closes #N` in the body keeps the link. **Overrides live in `pnpm-workspace.yaml`, not `package.json`** — pnpm 11 ignores that field with a WARNING, so the old recipe passed every gate and changed nothing. **There are two manifests plus the Actions pins** — root (pnpm), `infra/` (npm), and the `@vN`-pinned workflow actions, which have no manifest and no lockfile at all. The runbook says which commands apply to which; for an actions advisory none of them do, and the fix is a hand edit in the workflow. **The runbook is [`docs/reference/DEPENDABOT.md`](docs/reference/DEPENDABOT.md)** — the alert query, the checkout→fetch→rebase→install→gates→review→squash sequence, and which of those steps fail silently. It lives there and not here because it carries measured figures, and a figure in this file goes stale in every session at once.
