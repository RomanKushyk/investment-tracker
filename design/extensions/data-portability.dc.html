Wide: one row per date, one column per asset. The trailing empty cell on 2026-07-27 is Energy's PENDING quote — no quote was saved that day. A literal 0 would mean the position was worth zero, and the two must never collapse into each other.
Long: date,assetId,quote — one row per quote; a pending quote is simply an absent row. Both layouts auto-detect from the header row, and the detected shape is stated in the dialog.
column matching — id first, then unique name
1 · the id in the LAST bracketed group wins — "Inzhur REIT (reit)" → reit (so an asset name may itself contain brackets).
2 · otherwise an exact trimmed, case-insensitive NAME match, and only when that name is unique in the dataset.
Anything else is a row error in the S4 list — pinned copy: Header column 3 — "OVDP" doesn't match any asset in live · Header column 3 — "OVDP" matches 2 assets in live — use the "Asset name (id)" form
