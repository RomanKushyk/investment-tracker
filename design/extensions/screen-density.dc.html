D-4 · The pending-change block is taken

Brief question 3, with its copy already drafted in § 2. Taken, because it is what makes an ALWAYS-PRESENT rail honest on a day with no coupon: without it the rail holds two rehoused elements, and the reason the rail exists — that the width goes "to the day and the portfolio" (brief F-3) — is never actually spoken.
It names the CHANGE and never the total (G-8). The sidebar already renders ЗАГАЛЬНИЙ КАПІТАЛ 149 016 ₴, the saved figure; a live total in the rail would be one quantity with two values on one screen. A change is a different quantity, and it is the only one this screen is in a position to know.
Stated as a requirement, not a formula (D77, and the last sheet's fourth round): the figure is the sum, over assets the draft has touched, of the drafted value less the same baseline the row beside it is already showing. Assets left alone contribute nothing — coalesce (D33) carries them forward unchanged, which is also why "partially filled" is not a state.
That baseline is yesterdayQuote(snapshots, assetId, selectedDate) — lastQuoteBefore, the last quote strictly BEFORE the picked date, which is exactly what every row's … ₴ учора subline reads. It is emphatically NOT latestQuotes, and the trap is worth naming because that function looks right: it is quotesAsOf with no bound (core/derive.ts:163), so on any day the date picker is not sitting on today it measures against a snapshot LATER than the one the rows compare to. The rail would say one thing and four sublines another — the one-quantity-two-values failure this block exists to avoid, let back in through the baseline.
And the baseline is per asset, so no single date may be printed beside it. Both resolvers merge per asset — an asset absent from the newest snapshot keeps its own last known quote, which is a deliberate documented property of quotesAsOf — so two assets can be measured against two different dates inside one sum. The sub-line therefore names the COUNT only. The date belongs to each row's own subline, where it is already per asset and already correct.
