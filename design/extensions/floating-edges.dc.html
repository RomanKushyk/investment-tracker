T2 · The shadow cannot carry it

#86 offers "no change, the shadow is the separation" as the honest alternative. Composited, it is not available as a 1.4.11 argument. These are UPPER BOUNDS: each is a plane composited with the shadow's full nominal alpha, which is the alpha under the occluded box. Outside the edge, with the blur and offset each shadow actually has, the visible step is roughly half — near 1.12 for --shadow-popover, near 1.17 for --shadow-dialog. The bound is the direction that flatters the alternative, which is why the bound is what is printed.

The veil is worth about what the stroke it would excuse is worth. So the shadow describes what a sighted user perceives and is never a finding of conformance. "No change" survives only as a recorded non-conformance — and unlike reit's 2.79 or the switch's dark 2.05, this one has a remedy inside the palette: row five of T1.

T4 · The ruling — the three names are retired, not re-valued

The first draft re-pointed three aliases at field-border and kept the names. Review asked the question that ruling implies and the draft never answered it: if all three hold one value in both themes, they are one step drawn three times, and index.css's own retired --color-label comment rules on exactly that — "Two tokens that must hold the same value to be legible are one step drawn twice. … Do not re-mint." So they are retired instead.

The palette goes 74 → 71 names per block. No hex is minted; three names leave and their seven consumers read the rank directly. index.css already calls field-border "the control-boundary rank" — a rank, not a field's private colour — and a floating surface's edge is a component boundary held to the same bar on the same planes.

WHY --color-switch-border IS NOT RETIRED WITH THEM, since it is also var(--color-field-border) in both blocks and the question is fair. Its name carries a reading that has nowhere else to live: the dark OFF edge against its own track, 2.05 : 1, a recorded shortfall index.css states beside that declaration and switch-border.test.ts pins. Retiring the name deletes the only place that reading is attached to. The three retired here carry no such record — nothing is written at their names that is not already written at field-border's — so there is nothing at them to keep.

THE TWO OVERLAY SURFACES ARE NOT FULLY REPAIRED, and the table says so rather than stamping them. They gain an identifiable boundary inward at 3.69, where before they had only a 2.65 fill step and a shadow worth about 1.17. Outward against the overlay the stroke is 1.20–1.39 on every plane, so the adjacency that separates them from the page behind still fails. That reading is #99's: closing it means moving the overlay or the panel, and #92 moves sidebar, which the overlay is 40 % of, so it may resolve there.

THE COST IS THE RAIL. A stroke there reads 3.35 outward on a plane already at 16.24 — a visible light outline down the sidebar, which index.css calls "decoration nothing asked for" and this file overrules rather than agrees with. It is accepted because the alternative is an exemption and an exemption cannot be written: the Dialog panel and the mobile date sheet are identical in fill, backdrop, fill step and both stroke readings while reading different tokens, so no rule about the surfaces can bound one family and not the other. That is what the first draft died of, and retiring the names removes the families it turned on.

--color-drawer-edge IS KEPT, the only floating edge left with a light value of its own. It has one consumer, the mobile drawer — the sidebar wall over --color-scrim, which is not the Dialog's bg-sidebar/40, a distinction --color-scrim's own comment is at pains to draw. Composited per plane the drawer reads 5.50 / 5.10 / 4.77, so its binding figure is 4.77 and it is identified without a stroke. It also differs per theme — transparent in light, sidebar-muted in dark — so unlike the three retired here it is not one step drawn twice.

Eleven boxes, five sheets, and the survey that found them is re-runnable: an inline style with a 1px hex border AND a radius of 10–24px AND either absolute/fixed positioning or a box-shadow whose blur is 8px or more. The blur floor is load-bearing — sibling sheets' own annotation cards carry --shadow-card's 3px blur, and without the floor the signature sweeps them in as if they were app surfaces. Two further matches are excluded with reasons: scroll-surface:171 is a scrollport diagram frame, appearance-language:1327 is dark. The master reference draws zero light floating surfaces and is untouched. This file draws five boxes of its own by that signature — its Select and toast pairs plus the Dialog "after" — so a reader re-running it subtracts five. That figure is computed from the file rather than counted by eye, which is how its first draft got the same number wrong twice. Nothing here supersedes geometry, copy or any dark value, and it edits none of them.
