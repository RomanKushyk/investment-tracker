# infra/migrations/drafts — schema written before anything may apply it

**Nothing in this directory is applied by any code.** That is the point of the folder: DSQL primary keys are immutable, so a key is decided on paper, reviewed, and only then promoted.

**Empty today.** `003_user_schema.sql` was promoted to [`../003_user_schema.sql`](../003_user_schema.sql) in the commit that gave it a handler entitled to run it — [`../../src/migrate.ts`](../../src/migrate.ts). The practice below survives the file, for the next key that has to be decided on paper.

## Local rules

- **`ensureSchema` (`../../src/capture.ts`) owns the ARCHIVE — `price_capture`, `price_observation`, `instrument` — and must not learn any other table.** That is provider data shared by every environment. User data splits dev from prod at W7 (`docs/DECISIONS.md`, **Cloud target**) and is applied by the runner, which names its files rather than globbing them.
- **Numbering continues `../`, and it is not a glob's business.** `001`, `002` and `004` are the archive's; `003` and `005` are the user schema's. `bond_terms` took `004` rather than `003` so that two files would never share a number — the ambiguity numbering exists to remove, and the reason a tool globbing `migrations/**/*.sql` by filename would run the user schema before the archive tables.
- **DSQL's DDL facts — what `CREATE INDEX` and `ALTER TABLE` accept or refuse, the create-time-only matrix, and the three promotion rewrite rules — live in [`../../docs/dsql-constraints.md`](../../docs/dsql-constraints.md), not repeated here.** How a promoted file is actually applied is [`../../src/migrate.ts`](../../src/migrate.ts)'s header.
- **Foreign keys ARE adopted, `ON DELETE RESTRICT`, never cascading** (`docs/DECISIONS.md`, **User schema and deletes**) — but not yet WRITTEN: [`../../schema/user.ts`](../../schema/user.ts) holds the ruling in comments and no `references()` call. All five will be table-level `foreignKey({ name, … }).onDelete('restrict')`, never a column-level `references()`, because only the former carries a name and this repo requires constraint names to match the generated SQL — so grepping for `references(` proves nothing either way.
- ~~**UNIQUE constraints are declared INLINE in `CREATE TABLE`, never as a later `CREATE UNIQUE INDEX`.**~~ Half of that is false — a later unique index works and enforces `23505`. The drafting convention stands anyway, for a different reason: the CONSTRAINT form is refused after creation, so inline is the only way to get a unique CONSTRAINT. Drizzle's `unique()` table builder, used throughout [`../../schema/user.ts`](../../schema/user.ts), emits it that way; its sibling `uniqueIndex()` emits a separate `CREATE UNIQUE INDEX` instead, and nothing here should reach for it.
- **A draft must keep [`../../src/user-schema.test.ts`](../../src/user-schema.test.ts) green.** It applies the user schema to a real Postgres (PGlite, in WASM) and exercises every constraint in both directions. `pnpm test` runs it locally and `.github/workflows/deploy-backend.yml` runs it in CI — together the reason a schema change cannot drift from what [`../../schema/user.ts`](../../schema/user.ts) claims.
- **Local Postgres proves nothing about DSQL — it is the subset.** The DSQL facts in [`../../docs/dsql-constraints.md`](../../docs/dsql-constraints.md), plus what a throwaway schema on the real cluster can be made to answer, are the whole of that safety; anything found to diverge belongs there. **Check the DSQL release notes before believing anything else on this page** — twice this repository recorded a DSQL limitation that a later release note had already lifted.
- **Promotion is a move, not a copy.** The file leaves this folder in the commit that gives it a handler entitled to run it, and [`../../README.md`](../../README.md)'s Layout table is corrected in the same commit. A generated file arrives carrying no contract header of its own — `001`, `002` and `004` carry theirs inline as comments; `003`'s live in [`../../schema/user.ts`](../../schema/user.ts) instead, beside the code they govern.
- **Measure against the app, not against the seed.** A claim checked against `src/lib/seed.ts` alone is not checked: `schemas.ts`, `TransactionPanel.tsx`, `repository.ts` and `core/backup/` all constrain what a writer will actually meet.
