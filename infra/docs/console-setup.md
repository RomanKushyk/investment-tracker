# infra — console setup, mail, and the Inzhur sanction check

Two roles, deliberately narrow: the GitHub role can only drive CloudFormation on one named stack and hand it the execution role, which alone holds the broad permissions — this is also why CDK is not used here, since its bootstrap execution role is `AdministratorAccess` by default. The OIDC provider already exists from the frontend setup (`docs/reference/DEPLOYMENT.md` §3.3) — do not create a second one. Replace `<account-id>` with the account's own id, deliberately not written down in this public repository. **The DSQL resource stays `cluster/*`** — cluster IDs are generated, not named, so there is no prefix to scope to, and the exec role can therefore reach every DSQL cluster in the account, old ones included; CloudFormation will not touch a cluster outside its own stack, but nothing else stops it either. The trust policy keys on the **environment**, not the branch; owner and repo carry immutable numeric IDs — both documented at length in `docs/reference/DEPLOYMENT.md` §3.3.

**The GitHub side is not here** — the two environments, their branch policies and the secret and variable each carries are one table in `docs/reference/DEPLOYMENT.md` §4, beside the OIDC trust policy that makes them the thing the role keys on.

**SES has no CloudFormation of its own.** What exists: the verified domain `quirenote.com` (Easy DKIM, custom MAIL FROM `mail.quirenote.com`, SPF on it, DMARC `p=none`), and configuration set **`quirenote-mail`** — the identity's DEFAULT set — with an event destination `problems-to-eventbridge` sending BOUNCE, COMPLAINT, REJECT, DELIVERY_DELAY and RENDERING_FAILURE to the default EventBridge bus, the same channel the alarms use (`docs/DECISIONS.md`, **Alerting**). The account is in the **sandbox**: 200 messages/day, 1/s, verified recipients only. Production access is what releases it, and it is granted per region. **It does NOT hold the approval flow shut, and this page said for a while that it did.** The pool sends its own mail: `DescribeUserPool` on the dev pool reads `EmailConfiguration.EmailSendingAccount: COGNITO_DEFAULT`, so the invitation that carries the only password a `FORCE_CHANGE_PASSWORD` account can sign in with never touches SES and reaches an unverified applicant. What the sandbox does hold shut is every message the APPLICATION itself sends, which is the reason production access is still wanted — measured, not inferred, and the pool's own setting is the thing to re-read before believing either story.

**Inbound is Cloudflare Email Routing, and it only ever receives.** Three addresses forward to the owner's personal inbox — `admin@`, `support@`, and `dmarc@`, which is not optional because the published DMARC record directs aggregate reports at it. There is no catch-all: it would make a mistyped address succeed silently instead of bouncing, and it invites every spam guess at the domain. Routing cannot SEND, and nothing yet sends AS one of these addresses: SES is the domain's only sender and carries the application's own mail, so a reply to anything arriving here leaves from the personal inbox under its own address. **Adding the addresses changed no DNS**, and the split is the reason: the apex SPF is Cloudflare's and answers for forwarding alone, while SES authenticates on `mail.quirenote.com`, the custom MAIL FROM its envelope sender already carries, and Easy DKIM signs `d=quirenote.com`, which aligns with a `From:` at the apex. So DMARC passes on DKIM, and the SPF it consults is `mail.quirenote.com`'s, never the apex's. **MX is single-occupancy**: hosting the mailboxes at a provider of their own would take those records and evict routing, which is the one choice here that is not cheaply reversible.

**Reading the Inzhur feed is sanctioned** — checked against ТОВ «ІНЖУР КЕПІТАЛ»'s client agreement and `https://www.inzhur.reit/robots.txt`: the deny list excludes `/dashboard/`, `/signin/`, `/signup/`, `/documents`, `/fund_merger_report`, `/annual_report_2025`, `/terms` and `/privacy-policy` — not `/_api/`. No clause in the contract prohibits automated access, and its confidentiality clause carves out information obtainable from public sources.
