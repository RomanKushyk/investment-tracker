## D106 — Nothing automated watches the dated gates (2026-08-28)

Owner's ruling, 2026-08-28. Split out of [`D104`](D104.md) — which records which
GitHub surfaces the repository uses — when a draft of it tripped the 200-line
diagnostic and the question it asks, *does this file hold a second purpose?*,
answered yes for this subject. The cap reports rather than compels (D98). The work-order ruling of the same day is
[`D105`](D105.md).

### The ruling

D103's *What this does not decide* said the dated gates in `PLAN-WAITING.md`
have nothing watching them, and that "a reminder is the candidate". **The
candidate is declined.** The mechanism is the table's own first rule — check it
first every session — and sessions landed on 21 of the 33 days from the
repository's first commit (2026-07-27) to 2026-08-28, longest gap 6 days.

- **Most gates OPEN rather than expire**, so arriving late costs waiting, not
  the item.
- **The table's `Hard?` column is the authority, and it names four: W5, W10,
  W11, W12.** W5 is below. The other three are W10's bond maturity
  **2027-03-24**, the AWS credits **2027-07-29**, and W12's bond maturity
  **2028-09-27** — 7, 11 and 25 months out, each read at dozens of sessions
  first. **W9 is marked `no`** although its cost line says "cached forever",
  and it takes the same present/read split as W5 below: the 01:00 run on 1 Jan
  writes 31 Dec by itself, so the date is not one a person must hit — but
  **sealing is a separate deliberate act**, and W9's first unticked box is *do
  not seal before verifying completeness for the whole year*. The
  irreversibility is `immutable` plus a strong ETag, not the capture. Arriving
  late costs nothing; sealing unread costs the year.

### W5 no longer needs anyone PRESENT; it still needs someone to READ

This distinction is the whole ruling, and stating it loosely is how the first
draft went wrong.

A6's nightly re-derivation measures the cum/ex boundary whether or not anyone is
watching, so a missed *day* costs nothing — and W5 warns against acting on the
day, which a watcher would push toward.

**The verdict is manual.** W5 keeps **three** unticked boxes: health-check
before 2026-09-22; read the window on 2026-09-24 or after and record where the
≈ 78.40 step falls; and **write the cum/ex convention into DECISIONS**, saying
whether it confirms `futureFlows`' same-day rule or overturns it. The third is
the one durable output and the easiest to skip, because the first two feel like
the work. **Cost of missing: 182 days**, and the next boundary is messier —
W10 pairs it with maturity.

**`UnexplainedQuoteAlarm` is not a detector for "the convention is wrong."** It
fires only when a quote cannot be explained by **any** yield the model can
produce, so a wrong-but-fittable convention is silent. The reminder was declined
because the table is read every session, **not** because W5 has nothing left in
it.

### A correction this ruling has to carry

Its first written justification claimed "every date left is inside four weeks".
That was false — the table runs to **2028-09-27** — and the same sentence
asserted that gates never expire, which W11 contradicts. The error came from a
grep scoped to `2026-`. A later draft then miscounted W5's remaining boxes as
two and dropped the DECISIONS entry, the one output the item exists for. Both
were caught by D76 review before the change merged, which is the argument for
that rule in one line — but each was load-bearing for this ruling, so they are
recorded rather than quietly fixed.
