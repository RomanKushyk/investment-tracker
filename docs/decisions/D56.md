## D56 — Nested radii are concentric, standalone radii are proportional (2026-08-12)

Capsules (`rounded-full`) were replaced with finite radii across the sidebar and
the quote rows. Two rules came out of that, and using the wrong one is what the
first attempt got wrong.

### Proportional, for a standalone control

`r = round(min(w, h) × 0.26)`, keyed to the **short side** — the short side is
what decides how capsule-like a shape reads. The ratio is measured, not chosen:
the lockup plate is 14px on a 54px block (36px circle + 10px padding), = 0.259.

It gives 10 (38px pill), 9 (36px pill), 7 (28px segment), 4–5 (badges), 20 (the
76px quote row — which is the existing `Card` default, so no new token).

### Concentric, for a box nested against a parent's corner

`outer = inner + gap`, so the two curves stay parallel. Sidebar: header plate 14
+ 16px inset = shell 30.

### A segmented control is BOTH rules at once, and I got it wrong first

A segmented control is a track wrapping segments at a uniform padding. The
segment sits in the track's own corner, so:

- the **segment** is an object → proportional: 28px tall → 7;
- the **track** is a container → concentric: `7 + its padding`.

Every track shipped with the track's own proportional value instead (0.26 of the
38px box → 10), which is not the same number and left the two curves diverging
at each corner. Corrected: sidebar toggle `7 + 6 = 13`, Settings and dataset
switches `7 + 4 = 11`, the asset-form switch `7 + 3 = 10`. The Total capital card
follows the sidebar toggle to 13, keeping the pairing it was given.

**Proportional describes an object; concentric describes containment.** A
segmented control is both at once, and reaching for the wrong one gives an
answer that looks derived while being arbitrary. The same mistake, one level up,
was the 63px shell.

### Where the first attempt broke

The proportional rule was applied to the sidebar shell too. A full-height panel's
short side is its width, so 244 × 0.26 gave **63px** — and a 63px corner cuts
straight across the header plate sitting 16px inside it. The plate's own corner
was being clipped by its parent.

**A rule derived from controls does not transfer to a container just because the
arithmetic still evaluates.** A panel's width is a layout consequence, not a
designed size, so scaling anything from it is meaningless. Concentricity is the
rule for containment; proportionality is the rule for objects.

### Two deliberate exceptions

- The **Total capital** card takes the toggle's radius rather than the shell's
  concentric 14: the two sit together as one bottom cluster and a shared radius
  reads as a pair. That one corner is knowingly not concentric with the shell.
  (Corrected 2026-08-12, same day: this paragraph first said "10", the value the
  toggle had before the segmented-control section above corrected it to 13. Both
  ship 13. The number is stated once, here, and derived once, there.)
- The **logo circle** and the decorative blob stay circles. A circle among
  rounded rectangles reads as deliberate — it is the mark, not another control.
  Rounding it too made it dissolve into the ribbon of everything else.

### Circle in a block

An avatar inside a row occupies **60–70%** of the row's height. The quote row is
a 48px circle in a 76px row = 63%. Note the feedback loop: enlarging the circle
raises the row, which raises the row's proportional radius — 48 + 28 = 76, and
0.26 × 76 = 20, which is the `Card` default. Height first, radius second.

### Applied across the app

Every capsule (`rounded-full`) in `src/` was measured in the running app and
given `round(h × 0.26)`. Heights are rendered, not computed from the classes —
`text-[11px]` sets a font size and not a line height, so the class string alone
cannot tell you how tall a control is.

| h | r | what |
| --- | --- | --- |
| 10–12 | 3 | allocation bar track and fills, `ShareBar` |
| 19 | 5 | micro badges (DEMO, provenance chip) |
| 22 | 6 | `Switch` track |
| 23–24 | 6 | `Tag` (the Attributes/Portfolio pill), status badges, `Σ 100%` |
| 26–28 | 7 | segmented-control segments and thumbs, dashed offer chip, calendar arrows |
| 30 | 8 | `Button` size `sm`, `AssetForm` segmented box |
| 32 | 8 | calendar day cells |
| 38–40 | 10 | `Button` sizes `header` and `md` |
| — | 13 / 12 / 11 | segmented-control TRACKS — concentric, not proportional: segment 7 + padding + any border (sidebar 7+6, Settings and dataset 7+4+1, asset form 7+3+1). See the section above; the table row that once listed them at 10 was the proportional value this decision rejects. |

`Button`'s radius lives in its `size` variant, beside the padding that sets the
height — same rule as `weight` and `size` themselves: never a className override
that two utilities can then fight over.

### Overlays, and the two things the first sweep missed

The sweep walked the routes, so it never opened anything. Opening them found two
more:

**Toasts were outside the system entirely.** `<Toaster />` was mounted bare, so
every toast used sonner's own look: radius 8, a `ui-sans-serif` system stack —
a third typeface in an app with two — and a pure-black shadow. Now radius 13
(the rule on its measured 51.5px height, the same number the currency toggle
lands on), `var(--font-body)`, and the app's own `0 4px 16px rgba(38,38,42,.12)`.
Set as inline styles via `toastOptions`, because sonner styles by attribute
(`[data-sonner-toast][data-styled=true]`) and that outranks any class we add.

**The Select popover was the segmented-control mistake again.** Its items sit in
its corners at a uniform 5px inset (4px viewport padding + 1px border) with
radius 9, so it is the concentric case: 9 + 5 = **14**, not the 16 a surface
takes. The DatePicker popover keeps 16 and the Dialog keeps 24 — their
corner-adjacent children are an absolutely-placed arrow and a form in flow, not
a box hugging all four corners. **Concentricity is not "a box inside a box"; it
is a rounded child whose corner has to stay parallel to its parent's.**

Verified by measurement with the overlay open: Dialog 24/padding 24 with 34px
controls at 9; DatePicker 16/padding 8, day cells 8, arrows 7; Select items 9;
chart tooltip 16.

### What stays a circle

`AssetAvatar`, `ColorDot`, the sidebar logo circle, and the decorative blob. A
circle among rounded rectangles reads as deliberate; rounding these too
dissolved them into the ribbon of everything else.

The `Switch` was the one open question — a capsule track plus a round knob gives
the "slides in a groove" affordance for free, and squaring it costs that. It was
squared anyway, knob included (16px → 4), because a lone capsule left in a UI
where nothing else is one reads as an oversight rather than as a convention.
Consistency won on purpose, not by omission.
