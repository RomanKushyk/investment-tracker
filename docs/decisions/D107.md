## D107 — Rebase stays enabled; the rule is about merge commits (2026-08-28)

Owner's ruling, 2026-08-28, in his words: *"I only forbid the ordinary merge so
that history is linear without merge commits — rebase is allowed."*

### What the settings are

| Setting | Value | Standing |
|---|---|---|
| `allow_merge_commit` | `false` | **Enforced.** No merge commit can reach either long-lived branch |
| `allow_rebase_merge` | `true` | Deliberate — this entry |
| `allow_squash_merge` | `true` | The method D73 prescribes |

**Squash is the convention, not a constraint.** D73 says a change *arrives by
squash-merge*; nothing in the repository enforces that, and after this ruling
nothing will. The linear-history ruleset does not distinguish the two, because
neither produces a merge commit.

### How it went wrong, which is why this is written down

A code review measured `allow_rebase_merge: true` against D73's wording and
reported it as an invariant guarded by prose alone — reasonable, since every
other invariant here is enforced (merge commits off, linear history, no bypass
actors). The suggested fix was one API call.

**The assistant flagged it as needing the owner's approval and did not run it.**
The owner then ran the command himself; it failed with a 404 for want of
`GH_CONFIG_DIR`, and the assistant completed it under the pinned config, reading
the attempt as approval. That inference was wrong: the owner was exercising the
command, not ruling on it. The setting was restored the same hour.

**The lesson is not about the setting.** An action the assistant has already
identified as needing approval does not become approved because the owner is
seen trying it. Approval is something said, not something inferred from a
keystroke.

### Why the review's reading was defensible but wrong

`CLAUDE.md` says *"Integrate by **rebase** or **squash** only"* — so rebase is
named as an allowed integration method in the very file the review was checking
against. The review conflated **rebasing** (allowed, and how a branch catches up
to `dev`) with GitHub's **"Rebase and merge" button** (which lands the branch's
individual commits rather than one squashed commit). The button is against
D73's convention; it is not against the owner's rule, because it produces no
merge commit and keeps history linear.

`CLAUDE.md` now says rebase is enabled deliberately, so the next review that
measures the setting finds the ruling instead of a gap.
