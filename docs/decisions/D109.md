## D109 — A nested checkout must be invisible to every tool that walks the repo (2026-08-29)

Found while verifying something else. A `/code-review` had just certified a branch
green; minutes later the same command on the same tree reported a different set of
files, because a background agent had opened two worktrees in between.

### What was measured

Two worktrees open at `.claude/worktrees/`, each a full checkout:

| Tool | Walked | Inside worktrees | How it failed |
|---|---|---|---|
| `git add -A` | — | 2 | staged them as **embedded git repositories** |
| eslint | 685 files | **456** | two thirds of every lint run |
| vitest | 225 test files | 150 | against a real suite of **75** — exactly 3 copies |
| prettier | — | 2 | `format:check` RED on `assets-sample.json` |
| `markdownFiles` walk | 0 | 0 | **correct already** |

`vitest`'s default exclude is only `**/node_modules/**` and `**/.git/**`. ESLint's
flat config defaults are equivalent. Neither reads `.gitignore`; prettier 3 does.

### The ruling

**`.claude/` HAS TWO HALVES AND ONLY ONE IS SCRATCH**, so the rule excludes the
contents and negates the shared entries back in:

```gitignore
**/.claude/*
!/.claude/settings.json
!/.claude/agents/
!/.claude/commands/
!/.claude/skills/
```

Scratch is the larger part — `worktrees/<name>/` (the nested checkout),
`settings.local.json` (personal, and this repository is PUBLIC), `todos/`, and
whatever `/loop` and `/schedule` keep. Shared is `settings.json`, `agents/`,
`commands/`, `skills/`: configuration a repository commits. An intermediate rule hid
both, so `/update-config` would write a permission allowlist and `git add -A` would
skip it in silence.

**Each part of the form is a measured decision:**

| written | instead of | because |
|---|---|---|
| `/*` | `/` | git cannot re-include a file whose parent DIRECTORY is excluded — a bare `.claude/` defeats every negation below it, silently |
| `**/` | nothing | a pattern containing a slash is ROOT-ANCHORED; `.claude/*` leaks `infra/.claude/…` while eslint and vitest match at any depth |
| `!/…` | `!**/…` | the negations are root-anchored on purpose: a nested `.claude/` is pure session state, with no shared half to rescue |

### The tools are asymmetric, and that is the ruling

Git commits the shared four. **eslint and vitest exclude `.claude` WHOLE** — a vendored
skill or agent is configuration, not this repository's source, and a `*.test.ts`
shipped under `.claude/skills/` was measured being collected into `pnpm test`.

Prettier follows git, so it reads all four negated entries — and with the other two
tools excluding the directory, it is then the ONLY gate that does, failing on files
nobody edited. `/update-config` writes `settings.json` with
`JSON.stringify(obj, null, 2)`, no trailing newline; a skill ships `scripts/*.js`,
`references/*.json` and `*.yaml` beside its Markdown. Measured: four files RED.
`.prettierignore` therefore takes **`.claude/`**, not `settings.json` — narrowing it
that way was tried and covered one file of the four. It wins the same argument the
lockfiles do: machine-written, never hand-edited.

`src/nested-checkouts.test.ts` asserts BOTH directions, so neither can drift: the four
stay visible to git and ignored by eslint, the scratch stays hidden from all of them.

`.prettierignore` gains **one entry, `.claude/`, and only because git tracks part of
that directory.** For everything else the file's existing claim holds — prettier
honours `.gitignore`, "so build output and scratch directories need no entry and none
is given", and a second statement of that rule would just drift. The shared four are
the exception that proves it: they are NOT gitignored, so prettier reads them, and it
is then the only gate that does. Narrowing the entry to `settings.json` was tried and
covered one file of four.


### Why one guard file and not four

`src/nested-checkouts.test.ts` holds all of it. Split per tool, three green files and
one red would read as a config nit; together they read as what it is. Git and eslint
are asked behaviourally — `git check-ignore`, `ESLint#isPathIgnored` — so the guard
survives the ignore moving between config objects or changing spelling, and each has
a negative anchor so it cannot pass by asking the wrong question — `package.json` for
git and prettier, but **`src/main.tsx` for eslint**, which reports `package.json` as
ignored under any config for the same reason the probes end in `.ts`. Prettier is asked too, via `getFileInfo` with `ignorePath`, which
is what its CLI does: "prettier honours `.gitignore`" is the load-bearing reason the
scratch needs no entry of its own there, and an unexercised reason is the one that
turns out wrong — as the shared half proved, being the one case where that reasoning
runs the other way.

**Every probe runs at the root AND nested under `infra/`.** The first guard probed one path per tool and no depth, so it asserted an
INTERSECTION and stayed green through exactly the divergences described above — a git
pattern containing a slash is root-anchored while the eslint and vitest spellings match
at any depth, which is a second axis entirely. The SHARED `.claude` entries are probed
too, in BOTH directions: visible to git, ignored by eslint. Asserting only one side
is how the asymmetry silently collapses toward whichever tool was edited last. The probe's `.ts` extension is
load-bearing in turn: `isPathIgnored` returns true for any path no `files` pattern
claims, so the `.json` spelling tried first made the eslint half vacuous — narrowing
`eslint.config.js` back to `**/.claude/worktrees` left the whole suite green.

### One list, three configs — and it is NOT `SKIP`

`PARITY` in `src/scratch-dirs.ts` is the list `.gitignore`, `eslint.config.js` and
`vitest.config.ts` must all name. None of them can import a TypeScript module, so each
restates it, and `src/nested-checkouts.test.ts` fails if any drifts.

**It is deliberately separate from `SKIP`.** `SKIP` answers "not ours to MEASURE" and
drives the Markdown, claim and distillation walks; `PARITY` answers "not ours to
TRACK". They overlap without coinciding: `SKIP` holds `.claude` whole — correct, since
a worktree's Markdown would double-count — while only `worktrees/` under it is
untrackable. Conflating them would push a future session to gitignore a directory the
repository commits; `design/` is the obvious candidate, already exempted in
`.prettierignore` for the same "not ours" reason. Only one direction is asserted:
everything hidden from the tools is outside the walk too.

`PARITY` lives in its own module rather than as a const inside the test, because a test
file importing another test file RE-EXECUTES its `describe` blocks — measured, the
suite reported 19 cases where there were 11.

They had already diverged **four** separate ways by the time this was written, each
found by a different review round: `.claude/worktrees` (all four tools), `.superpowers`
(**eslint was measured linting a live `verify.ts` there**, and vitest collected a probe
test), `.vite`/`.turbo` (absent from `.gitignore` alone), and `coverage` — named by
**none** of the three, so a single `vitest --coverage` run would have left an untracked
directory and a red `format:check` on generated HTML, reproducing this whole ruling
against a directory nothing guarded. An earlier guard filtered to DOT-directories,
which is exactly what hid `coverage`. Restating a list in three places is a fact of
these tools; letting the copies drift silently is not.

`src/vitest-scope.test.ts` is tied to the same list. Its rule is that every ADDED
exclusion must name a directory `PARITY` holds — not, as a first version had it, that the
pattern be shaped `**/.<dot-dir>/**`. That shape was a proxy for "cannot match
`infra/src`" and it rejected `**/dist/**` and `**/coverage/**`, both correct. Neither
`infra` nor `src` is in `PARITY`; that is the invariant, and TypeScript proves it at
compile time — against the literal union the comparison is rejected outright (TS2367).

**The probes cover two axes, because the first version covered neither fully.** Sibling
(`.claude/agents/…` vs `.claude/worktrees/…`) catches configs disagreeing about WHAT
inside `.claude` is hidden; nested (`infra/.claude/…`) catches them disagreeing about
DEPTH, which is invisible to any top-level probe. And `git check-ignore` runs with
`-c core.excludesFile=`: it otherwise merges the user's GLOBAL excludes, and this
machine's `~/.config/git/ignore` already carries `**/.claude/settings.local.json` —
measured, with the repo rule deleted git still answered "ignored" and cited that file.
Unpinned, a developer whose global ignore holds `.claude/` could delete the rule and
keep both a green suite and a green local `/code-review`. **`.git/info/exclude` cannot
be switched off by any flag**, so the behavioural probe is paired with a textual one
asserting the repository's OWN file names each directory: neither is sufficient alone —
the textual check cannot see a rule that fails to match, and the behavioural one cannot
see where the answer came from. **This ruling's own thesis
applies to its guard first.**

**Vitest is the exception, and is asked structurally.** Its exclude is matched by
tinyglobby, and no glob engine — picomatch, tinyglobby, minimatch — is resolvable at
the root under pnpm's strict layout, so there is nothing available to ask "does this
pattern match?". That assertion is literal string containment, and a behaviourally
identical `'**/.claude/**/*'` would fail it. `git check-ignore` also distinguishes exit 1 ("not
ignored") from 128 (git missing, dubious ownership, not a checkout): swallowing 128
would fail the test pointing at `.gitignore` for an environment problem.

Importing `eslint.config.js` to read its `ignores` array was tried first and does not
typecheck: that file is outside the root tsconfig program, so `TS7016` fires on the
import before any assertion runs.

### What this is really about

The waste was never the point. `pnpm lint` and `pnpm test` gave different answers
depending on whether an agent happened to be running — and the gates are what every
merge in this repository rests on ([`D76`](D76.md)). A verdict that moves with
background state is not a verdict, and every green run recorded while a worktree was
open proved less than it appeared to.

`src/vitest-scope.test.ts` guards the complementary risk from the same config: that
some future exclusion, added for any reason, quietly takes `infra/src` with it.
