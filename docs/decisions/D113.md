> Decision log entry. Index and the rules: [`RULES.md`](RULES.md). Cited from code and docs as bare `D113` — the number never changes, and this entry is never rewritten, only superseded.

## D113 — The backup envelope is formatVersion 2 (2026-08-31)

[`D112`](D112.md) puts `quantity` and `unitPrice` on `Transaction`. The envelope's
rows are `z.strictObject`, so a build that has not declared those keys rejects a
file carrying them — with `unrecognized_keys`, which names a field where a version
belongs.

**[`D12`](D12.md)'s forward-compatibility mechanism is why this was needed, not a
failure of it.** That decision's rule is exact: declare an optional field BEFORE it
ships and the older build already accepts it, so `formatVersion` stays put. These
two fields shipped in the same commit as their writer. Nothing pre-declared them,
and nothing could have.

## The break runs backwards, and it was accepted

Bumping the version does not help the forward direction at all — an old build still
refuses the file, only with a clearer sentence. What the bump does is refuse **every
v1 file on disk**, because `readEnvelopeHead` tests strict equality.

**Accepted by the owner, 2026-08-31:** the platform has no live users and their own
data can be deleted.

That is not a new position here. [`D42`](D42.md) kept the `kubushka-backup` marker
through the rename **for exactly this reason** — "renaming it makes every backup ever
exported unreadable" — and the owner reversed it during E1 on the same grounds, one
user and no real data. `import.ts` carries that amendment within fifty lines of the
code this decision changes.

## Three rejection codes, not two

[`D24`](D24.md) pinned two: `newer-format` for a file from a future app, and
`unsupported-format` for anything else unreadable. A v1 file now falls in neither
honestly — it is a real backup this app has moved past, and giving it the same
sentence as a hand-edited `0` tells the owner their file is broken when it is not.

| version seen | code |
|---|---|
| `> 2` | `newer-format` |
| `1` | **`older-format`** |
| non-numeric, `0`, negative | `unsupported-format` |

## What is superseded, precisely

- **D24** — "Envelope version policy: `formatVersion` 1 is current; a NEWER version
  is …" and its two-case table.
- **D12** — the envelope literal `formatVersion: 1`, and "a non-1 `formatVersion` is
  rejected before the row schemas".

Everything else in both stands: the pure `buildBackup` signature, the
caller-supplied `exportedAt`/`dbVersion`, `z.strictObject` rows, the post-parse
referential integrity, and the row-addressing scheme.

## What this does not license

A version bump for an ADDITIVE field is still the wrong move, and D12's rule is the
one to reach for: declare it optional first, ship the writer later. The bump here is
the cost of two fields that could not be pre-declared, paid once, on a dataset with
no other reader.
