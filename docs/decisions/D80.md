## D80

**The selected window DOES change `Річна`'s `daysHeld` basis — and the grey that
makes it honest ships with it.** Owner's ruling, 2026-08-24, on [O24].

**This supersedes the Phase 6 pinned trap fix** in `NEXT-PHASE-PLAN.md`
("annualized keeps the PORTFOLIO_START `daysHeld` basis regardless of window"),
which `PLAN-WAITING.md` called non-negotiable. It was not overruled lightly and
it was not wrong when written: with one window there was no way to see what it
was protecting against. The merged Phase 8 sheet (F-2) measured it — …6475, one
holding, one closing value, three windows: **+10,9 % (174 d) → +20,8 % (91 d) →
+33,6 % (30 d)** while Δ moves +5,20 → +5,20 → +2,76. **The sheet prints +33,7
and +2,77 there**; the shipped builder renders +33,6 and +2,76, and
`navigation-map.md` already pinned those. That is D78's boundary day, not a
disagreement — the sheet values a window's opening position on its `from`
where the code values it the day BEFORE. The measured figures are the code's. The pin's reasoning —
*"a range filter that changes an annualised figure is a wrong figure, not a
filtered one"* — is answered by the sheet's own finding: the distortion is
`annualizedPct`'s linear shape, not something the window introduces. A window
that left the denominator alone would report a rate for a period it did not
measure.

**BUT THE AMPLIFICATION DOES NOT SHIP ALONE, and that is the half A39 missed.**
It landed on `dev` on 2026-08-21 with none of F-3's treatment, and nobody chose
that combination — it was found by the v1.8.0 release review three days later.
The grey is now built: the `Річна` and `проти очікуваної` cells of a marked row
render `muted` #696865, **in every window including `Від початку`**, because the
distortion has always been there at the default and a treatment that fired only
under a window would be inconsistent with the screen it opens on.

**WHERE THE LINE FALLS WAS THE SHEET'S ONE DELEGATION** — *"a `core/` question
about the metric, not a colour question, and this sheet does not answer it."*
`basisIsShort` marks a row whose holding falls more than **10 %** short of the
basis it is divided by. Measured on the seed's 174-day basis: REIT and Energy
0 %, …8976 **1,15 %** (two days), …6475 **68,39 %**. Any threshold between the
last two satisfies the sheet's two pinned cases; 10 % is chosen because an asset
present for `h` of `n` days has its rate understated by exactly `n / h`, so a
10 % shortfall moves this portfolio's 10–11 % rates by ~1,2 pp — and `проти
очікуваної` is denominated in percentage points, where one point is the smallest
error that changes what the column claims.

**The predicate the sheet DELETED stays deleted:** "first purchase after the
window's `from`" fires on …8976's two days and would mark three cells while the
drawing shows two. The shipped legend says what the code tests, not what that
predicate would have: *«Сірим — річна поділена на строк, довший за фактичне
володіння активом, тож ставка занижена.»*

**Not a suppression.** Every D5-pinned figure is reproducible byte for byte —
…6475 still reads +10,9 % at `Від початку` — and a test says so. The mark means
trust it less, the signal the XIRR column already uses for null.

**WHAT THE GREY DOES NOT COVER, stated because the commit that introduced it
first implied otherwise.** F-2 and F-3 are two findings about two distortions.
F-3's grey marks a row ANNUALIZED OVER A BASIS IT DID NOT LIVE THROUGH — an
asset younger than the window. F-2's amplification is the window's own `365 / n`
scaling, which hits EVERY row equally: under `1 місяць` …6475 reads **+33,6 %**
with no mark, because it lived through all 30 days and the sheet's errata says
in as many words not to pin that case. F-2's own treatment is **S6/C1's
demotion** of `Річна` in the column hierarchy, and the sheet keeps it
deliberately separate — *"S6/C1 changes them; keeping the two apart is what lets
the owner take the window without taking the hierarchy."* **S6/C1 has not
shipped.** So a short window still amplifies without a mark; that is F-2's open
half, not a gap in this one.

**[O23] is still open** and interacts: if annualization moves to each asset's own
holding period, most of what this greys stops being wrong and starts being
right. D80 marks the figure; O23 asks whether to fix it.
