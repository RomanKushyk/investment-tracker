## D74 — The funds' `nav` history is archived and never shown; the read-time conversion is rejected permanently — closes O21

**2026-08-18.** Owner ruling, closing `PLAN-OPEN.md` O21. The provider's Excel
files turned out to be a **different basis** from the one the app values in, so
"import the history" split into two questions. Storing was already settled
(`PLAN-WAITING.md` W15). This is the other half.

> **The `nav` series is archived as published and no screen reads it. Converting
> it to `sell` at read time is rejected, and rejected permanently rather than
> deferred.**

**The constraint this sits inside, restated so it is not re-litigated.** The app
values holdings at `sell`, because that is the amount actually realisable. A
nav/sell toggle was declined on 2026-08-18: `nav` reads **0** for `ocean-plaza`
and `zhytniy` (D31), so the toggle would blank two of four funds — and unlike
currency, language and theme, it would change what every derived figure MEANS
rather than how it looks.

**Why "never shown" rather than "shown as its own labelled series".** The two
readings differ in WHEN, not in WHETHER. The rows are written either way, so
nothing is lost and nothing is foreclosed: a second price line can be drawn the
day someone wants to look at one. Choosing it today buys a design session (G7 —
a new visual claim, and the app has never drawn a second price line) for a
series nobody has asked to see, and which exists for only two of the four funds.
**This is "not now", not "never"** — and reopening it means a brief, not a
component.

**Why the read-time conversion is rejected outright, and this is the part with
teeth.** It is the only reading that would give historical portfolio value, and
it fails on evidence rather than on taste:

- **The 0.9 % spread is undocumented.** The services agreement pins no NAV
  formula; the 0.5 % it does name is a referral early-sale fee, a different
  thing that has been mistaken for this one already.
- **It is verifiable over 75 days** — 2026-04-23 → 2026-07-06, the owner's own
  tracker — against a history reaching back to **2024-11-14**. Every figure
  before April 2026 would carry an unverified constant.
- **And it would be presented as portfolio value**, which is the failure this
  project has now refused three times: D31 archives the premises and never the
  conclusion; D69 declined to store a derived FX rate for the same reason; A6's
  last box forbids writing a conclusion into an append-only archive in as many
  words. Converting at read time does not store it, but it does hand the user a
  number that looks measured and is assumed.

**What this does NOT change.** W15 is untouched — every row still lands, `basis =
'nav'`, unconverted, gated on W4. The evidence stays in
`docs/reference/INZHUR-FUND-HISTORY.md`, including the 0.9 % measurement, which
is worth keeping precisely because it is the thing being declined. The 35-day
gap (2026-07-07 → 2026-08-10) is a separate question and is still open there.
