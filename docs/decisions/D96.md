## D96 — One file per decision; the range files are retired (2026-08-26)

**The append rule and the 200-line cap did not compose, and D95 said so while
being appended to a 1,016-line file.** The old rule sent every new entry to the
bottom of the highest-numbered range file; at an average entry of 55 lines, a
200-line file overflows on its fourth. Two rules, each sensible, that guarantee
a violation every third entry.

**Resolved by removing the thing they disagreed about.** A range file was only
ever a bucket. **Each decision is now its own file, `D<n>.md`**, named exactly
as it is cited — `D5` is `D5.md`. The append rule becomes *create the file*,
which can never overflow, and the cap becomes automatic: measured across all 95
entries the average is 55 lines and **the largest, D66, is 162** — no entry has
ever come close to 200.

**What this ends, concretely:**

- `D41-D50.md` held D41–D60 because the rule at the time said to append until
  D60. Its name was a fossil, documented as one, kept because renaming would
  "break nothing but help nobody".
- `D61-D80.md` held D81–D83 for a day in August because nobody noticed the file
  had passed its own name.
- Both were the same failure — a filename asserting a range it does not hold —
  and neither is possible now. **A file named `D66.md` holds D66.**

**Rules that did NOT change, and must not:**

- **Numbers never change.** ~20 citations in `src/` and `docs/` are bare numbers.
- **Never rewrite an entry — supersede it.** `D43.md` still carries the original
  wrong diagnosis directly under its replacement, in one file, because the two
  belong together: being wrong about *which* of five explanations held is the
  reusable part.
- **A contract change still requires an entry.**
- `README.md` is still the one place every decision is listed, one line each,
  and it is now also the map from a number to its file — the filename makes that
  mapping mechanical rather than something the index has to be trusted for.

**The five range files' headers are not preserved as files.** They said nothing
but which numbers a bucket held and where to append next — bookkeeping for a
scheme that no longer exists. What was load-bearing in them is above: the
`D41-D50` fossil, the `D61-D80` overflow, and the reason both happened.

**Both halves are now enforced, not merely written down.**
`src/docs-line-cap.test.ts` fails the suite if any Markdown file exceeds 200
lines, if a `D<n>-D<m>.md` range file reappears, if a decision file is named
anything but `D<n>.md`, or if the sequence has a gap. It was added because this
branch is its own evidence of drift: D95's measured figures went stale inside
three commits, and `.prettierignore` excludes Markdown at every depth, so no gate
step had ever read a documentation file. A rule restated in six documents and
checked by nobody is the "green because nothing was attempted" pattern this log
already catalogues at D43, D44, D48, D53, D89 and D91.

**Cost, stated plainly.** 95 files in one folder, and a plain directory listing
sorts them lexically (`D1`, `D10`, `D100`, `D11`), which is ugly. Zero-padding
would fix the listing and break the thing that matters more — a filename that is
the citation. `README.md` is the ordered index; the folder is addressed by name,
not browsed.
