## D117 — The Units field leaves the asset form (2026-08-31)

Owner, 2026-08-31, with a screenshot of the TransactionPanel's quick-create: **two
«Одиниці» fields on one screen at once** — the Inzhur link group's, and the
transaction's own, added hours earlier by [`D112`](D112.md).

They are not two questions. In quick-create the transaction being recorded IS the
asset's first purchase, so the group was asking for a count the row beneath it
already carried. And after D112 units are `Σ transaction.quantity` everywhere else
too, which left the field with nothing to be.

[`D112`](D112.md) deferred this removal, on the grounds that the stored value is the
only seed for the W7 backfill. That reasoning was right and is **why the property
survives** — it is the field that goes, not the number.

## The property is legacy, not deleted

`Asset.inzhur.units` becomes optional and is **never written again**:

- a link made **before** today keeps its count, and `matchAssets` still falls back
  to it, so no linked position stops valuing before the backfill;
- a link made **after** today carries no count at all;
- `csv.ts` still exports it and the JSON backup still reads it — a value nothing
  writes any more still has to be able to leave the database.

## Three ways this could have been a silent deletion

**1. The wholesale patch.** `assetPatchFromForm` sets `inzhur: values.inzhur`, so
the moment `units` left the form values, every edit of a linked asset would have
deleted the stored count — the exact failure `fixedCouponFields`' own comment guards
against for `reinvestPolicy`, arriving through a different door.

It now carries the legacy value across, **and only while the link is unchanged**.
Kind and ref are compared trimmed and case-folded, the way `matchAssets` compares
refs, because that is what decides whether two names mean the same instrument. A
count was counted for ONE instrument: re-point the link and carrying the number over
would value the new holding at the old one's size — a bigger version of #31.

**2. The round trip.** `assetFormDefaults` deliberately does **not** prefill the
legacy value. It survives because nothing writes it back; the moment it round-trips
through a formatter and a parser it is one bad parse from being destroyed — which is
not hypothetical, it is what the test in `asset-form.test.ts` was originally written
for (English formats 6164 as `6,164`, read back as 6.164).

**3. The third state.** `matchAssets` used to know units two ways. Now there is a
third: no quantities in the ledger AND no legacy total. That case yields a match
with **no `value`** — the asset still matched, it is in the feed, so it stays in
`linked` — and `reconcileFetched` skips it.

Not `undefined` written into a draft, and **not 0**: zero is a real answer, and it
is the one a sold-out position gives. Silence is the honest output when no count is
known.

## Also removed

The Fund/Bond segment went in [`D116`](D116.md) and the Units field goes here, so
**turning "Link to Inzhur" on now reveals exactly one control** — the ref picker.
Six now-orphaned dictionary entries (`asset.field.units`, `asset.placeholder.units`,
`asset.message.units`, in both languages) went with it.
