## D92

**Cross-browser beats offline, and the PWA shell leaves W7 (2026-08-25)**

An owner ruling, made while preparing W7: when the two trade off, working the
same in every browser matters more than working without a network. Recorded
because W7's scope was the first place the trade-off had a price, and because
the priority outlives this one deletion — future scope decisions inherit it.

**What the shell was actually buying.** The cloud-stack spec (2026-08-04) had
already renounced offline — its PWA row reads "installable shell,
network-required, no offline". And installability itself no longer needs a
service worker: Chrome dropped that requirement for install, and Safari's
add-to-home-screen never had one. Yet vite-plugin-pwa still ships a service
worker by default — the most browser-divergent layer the plan contained
(Safari's lifecycle is the canonical offender), plus a standing
update-and-cache surface to debug on every deploy. So the plugin's machinery
was all cost twice over: a service worker bought for an offline the spec had
already given up, guarding an installability that does not need one.

**The ruling.** "PWA shell" is removed from W7's remaining scope. W7 stays:
Cognito auth, user schema in DSQL, API Gateway + API Lambda, `repository.ts`
as an HTTP client, test repair, cutover. This supersedes the spec's
`PWA | vite-plugin-pwa` row and the "PWA shell" item in its Phase 3 scope, and
both places now carry an in-place pointer to this entry — the same way that
file already annotates D91, and the way D71/D72 actually handled a superseded
rule: the documents that INSTRUCT were corrected (the migration file's `as_of`
comment was rewritten in the D71 commit; only the data-model spec's pin, which
records rather than instructs, was left as written). The spec's Phase 3 list
instructs W7, so it gets the pointer.

**What this does not decide.** Installability without a service worker — a
bare manifest, cheap and reversible — is not W7's problem and is filed as
`PLAN-OPEN.md` **O29** so it outlives this paragraph. Nothing else in W7
changes. And the server-side derivation boundary that the same conversation
opened (what the backend may compute now that offline is not a constraint) is
an open question, not part of this ruling — filed as `PLAN-OPEN.md` **O28**,
with the spec's pinned `Derivation | 100% client-side` row annotated as
questioned by it; that row stays binding until a decision at W7 design rules.
