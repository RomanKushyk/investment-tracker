## D136 — the derivation moves to the server (2026-09-03)

`PLAN-OPEN.md` **O28** has been open since 2026-08-25, raised by the owner while
preparing W7 in the conversation that produced [D92](D92.md). It asked what the
backend may compute, and when.

**Read the spec first.** The owner ruled *спершу специфікація, потім рішення*,
so the working is in
[`../superpowers/specs/2026-09-03-w7-read-surface-design.md`](../superpowers/specs/2026-09-03-w7-read-surface-design.md)
and this entry is the ruling over it, not a summary of it.

## The ruling

**Derivation moves to the server at W7.** The cloud-stack spec's pinned row —
`Derivation | 100% client-side. src/core/ untouched. Server ships raw rows,
never aggregates` — is **superseded**, not annotated.

**It is an import, not a port.** `infra/src/capture.ts:19,23,27` already imports the three modules
`src/core/dates`, `inzhur/parse` and `nbu/fair-value`. The API Lambda imports
`src/core/derive.ts` the same way. **One implementation, one test suite**, which
is why the strongest objection to server derivation — two answers for one number
with nothing checking they agree — does not arise. **It would arise the moment
anyone reimplements rather than imports**, and that is the line.

**The read surface splits by SHAPE, not by screen**, and the owner's own
instruction was that the screens be combined:

| Endpoint | Carries |
|---|---|
| `GET /view` | every KPI and per-asset row set, **all 6 periods at once**, in ₴ plus `fx`. **No parameters** |
| `GET /view/series?period` | the yield curve |
| `GET /view/balances?page` | the Balances table |
| `GET /state` | raw rows, **export and import only** |
| `POST /mutations` | **unchanged** |

## Why three reads and not one

A measurement, and it is the load-bearing one. `YieldSeriesPoint` is
`{ date, [assetId]: number }` and `BalanceRow` is one cell per asset per date —
**both are the same width as a snapshot**, so deriving them server-side moves
the work and not the bytes. At 20 assets over 3 650 snapshots the curve is
~73 000 numbers, and shipping it for six periods is not viable. The KPIs
collapse; those two do not. **Splitting by screen would have cut across that
line; splitting by shape follows it.**

## Why `/view` takes no parameters

`PERIOD_OPTIONS` is six values (`src/core/period.ts:24`) and currency is one
multiplication. So all six blocks ship together in ₴ with the rate beside them,
and **period and currency cost zero requests** — the client picks a block, or
multiplies. That is what keeps the *fluid, soft motion on every interaction*
requirement intact, and an endpoint with no parameters has **one cache entry per
user per `data_version`**, which is the cache-key combinatorics the 2026-08-25
four-tier direction flagged, removed rather than managed.

## What the client keeps

**One field: `theme`.** `index.html:27` reads it in a script that runs before
the module bundle, so the first paint is already right; a round trip there is a
white flash on every load.

**`dataset` moves, and the reason it once could not is instructive.** It is
resolved synchronously at module init (`src/lib/db.ts:64`) because it binds a
Dexie database — and W7 *"retires D2 (IndexedDB), D16/G4 (demo+live split) and
the dataset guards"* (`phase-w-i-ii-iii.md`). **The constraint dies with the
thing that created it.** A first draft of the spec kept `dataset` client-side on
that stale reasoning and the owner corrected it.

A53 §2 is untouched: the three per-device `meta` keys stay per-device. They are
caches of provider payloads, not preferences.

## `usdRate`, and a contract retired on purpose

**Stored nowhere. A5/G5's user-owned override is retired.** The owner's
instruction was *"він потрібний лише в момент показу і може тягнутись (і
тягнеться) з API НБУ"*, and two facts were put back to them before it was taken
as a ruling:

- **it is manual-only and propose-only** — `useNbuRate.ts:5` (*"only the user's
  press in Settings ever stores it"*) and `NbuRateFetch.tsx:3` (*"It PROPOSES …
  a manual override the user owns"*). Removing storage removes the ability to
  pin a rate;
- **the backend cannot serve it from the archive.** [D69](D69.md) supersedes
  [D30](D30.md) on exactly this — *"the provider's FX rate is not stored at
  all"* — and `infra/migrations/001_price_capture.sql:101` says *"THERE IS
  DELIBERATELY NO FX COLUMN HERE … Do not add it."* What is recoverable from a
  payload by `buyUAH / buyUSD` is **Inzhur's dealer conversion**, not the NBU
  official rate this field shows; D69 measured it as neither one rate (44.7579
  against 44.8305) nor exact. Substituting it merges two bases, which D26/D27
  forbid.

**Ruled anyway, and ruled twice:** the override goes, and **the SERVER fetches
NBU** so `/view` carries `fx` — one request for every viewer and no browser
dependency on NBU's CORS. The cost is a new outbound call on a backend path that
had none. The reach is ten non-test files, and **the backup envelope drops the
field while the importer must accept an old backup carrying one and ignore it**
— a backup must not pin last year's rate onto today's screen.

## The reversal, on the record

**A ruling that RE-AFFIRMED 100% client-side derivation was drafted on
2026-09-03 and discarded unmerged the same day**, when the owner's direction
arrived. Nothing of it reached `dev`. It is recorded because the argument it
made is the one a future session will re-make: that the client already receives
every row, so materializing adds a second source of truth for free numbers.
**What answered it was the import** — one implementation cannot be a second
source of truth — **and the owner's priority**, which is that the client should
receive ready data.

## What this supersedes, and what it does not

**Superseded:** the cloud-stack spec's `Derivation | 100% client-side` row;
A53 `W7-API-CONTRACT.md` §1's rows 1–3, which mapped `listAssets`,
`listSnapshots` and `listTransactions` to `GET /state`; A5/G5's propose-only
`usdRate` contract.

**Amended:** `CLAUDE.md`'s shared-files rule. It enumerates **eight** files, and
`derive.ts` is not among them — nor `accrual.ts`, `period.ts`, `xirr.ts`, or the
eight `src/screens/*/` view-model modules. Server derivation grows that list by
roughly a dozen, and the `pnpm exec tsc --noEmit -p infra` gate is keyed to the
enumeration, so **W7's implementation task owes that amendment**.

**Not touched:** [D92](D92.md)'s cross-browser-beats-offline ranking, which is
re-affirmed rather than changed — settings moving server-side is what finally
delivers it. `POST /mutations`. **O33**, deletion. **W8's three reserved
questions** about the demo play copy. The `/view` payload's field-by-field
schema, which the spec pins only as the union of the existing view-model
interfaces.
