## D54 — The brand fonts cannot write the app's default language (2026-08-12)

**Decision:** `Spline Sans Mono` → **JetBrains Mono**, `Space Grotesk` →
**Rubik**. Both OFL-1.1, both via `@fontsource`, chosen by measurement.

### The defect, and where it came from

The phase-5 brief (A8) made Ukrainian the default language without checking
that the app could draw it. Measured from the installed packages: the two brand
faces cover **1 of the 67 characters Ukrainian needs**, and that one is the
apostrophe. `@fontsource/spline-sans-mono` ships 40 files, every one of them
`latin`; `space-grotesk` ships `latin` and `vietnamese`. Nothing Cyrillic exists
in either.

The consequence would not have been a missing glyph — it would have been the
**entire app** rendering in a system fallback the moment the default language
applied. Different face, different metrics, on every screen.

**The brief created this and the design session caught it.** That is the
pipeline working: a separate session reading the brief without the assumptions
of whoever wrote it. It is also the argument for G7 existing at all.

### Chosen by measurement, not description

Ten candidates were parsed directly (WOFF tables: `head`, `hhea`, `hmtx`,
`OS/2`, `cmap`) rather than compared by reputation.

| Role | Was | Now | The number that decided it |
|---|---|---|---|
| Body | Spline Sans Mono — x 0.5455, cap 0.727, advance **0.6em** | **JetBrains Mono** — x 0.550, cap 0.730, advance **0.6em** | Identical advance, so **no table, column or sidebar width moves by a pixel**; nearest of the five on both vertical proportions |
| Display | Space Grotesk — x 0.486, cap 0.700 | **IBM Plex Sans** — x 0.516, cap 0.698 | **Figures tabular by default** — a money column aligns with no CSS to remember |

All five monospace candidates measured 0.6em, so the layout was safe whichever
was picked — the vertical proportions broke the tie. **This contradicted the
design session's own proposal of IBM Plex Mono**, whose x-height (0.516)
deviates from the incumbent six times further than JetBrains Mono's.

### What is knowingly lost

Space Grotesk's x-height is unusually low (0.486) and that lowness was part of
its character. No Cyrillic-capable face reproduces it — every candidate measured
between 0.520 and 0.569. Rubik is the closest that also keeps the cap-height, so
the app's voice changes slightly. Accepted: the alternative was keeping a
typeface that cannot write the language the app now defaults to.

### The reference now diverges from the app, deliberately

`design/Investment Tracker.dc.html` is immutable (D14) and still specifies the
old pair. The app no longer matches it on this one axis. Recorded in
`README.md`, `CLAUDE.md` and `src/README.md` so the divergence is never read as
drift. Because the mono advance is identical, **every width and column
measurement in the reference remains valid.**

### One defect this uncovered

`AllocationDonut.tsx` hard-coded `fontFamily: 'Space Grotesk, sans-serif'` in a
Recharts `<Label>` style. Recharts takes strings, which is how a literal font
name survived a codebase that otherwise uses tokens — and it would have become a
silent system fallback the moment the package left `package.json`. Now
`var(--font-display)`. Worth remembering: **string-typed style props are where
tokens leak.**
