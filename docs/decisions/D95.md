## D95

**No documentation file exceeds 200 lines — the plans split the way the
decision log did (2026-08-26)**

`PLAN-NOW.md` had reached **2,211 lines**, of which three tasks were live and
51 were closed. That is the same failure D-era `DECISIONS.md` hit at 2,219 lines
and for the same reason: **the file every session is told to read first became
the file a session cannot afford to read in full.** A closed task's body is not
harmless there — it is read, weighed and skipped, once per session, forever.

**The cap is 200 lines, and it is a directive, not a target.** A file that
would cross it splits *before* the next entry lands, not after.

**The shape is `docs/decisions/`'s, because that split already proved out:**

- The plan file keeps its **path and its name** — `PLAN-NOW.md`,
  `PLAN-WAITING.md`, `PLAN-OPEN.md`, `archive/BUILD-PLAN.md` — and becomes the
  index: the rules, the Status/dated table, and a range table naming what holds
  each body. ~46 files across `src/`, `docs/`, `infra/` and `CLAUDE.md` cite
  those four paths; keeping them cost nothing and saved every citation.
- Bodies move into range files named for the IDs they hold — `A01-A20.md`,
  `W02-W08.md`, `O05-O29.md`. Ranges are cut to fit the cap, not to look round;
  `D41-D50.md` holding D41–D60 is the fossil that rule exists to avoid.
- **Moving is not rewriting.** Every body was cut by line range and moved
  byte-identical. Nothing was summarised, re-ordered inside a section, or
  "tidied" — that is the one operation that breaks a caller.
- **IDs never change.** `A20`, `E3`, `W7`, `O26` still resolve.
- **A citation that names a closed task still lands somewhere useful.** Roughly
  a dozen references — from entries in this log, from the design briefs, from
  `navigation-map.md` and from `src/core/derive.ts` — say things like
  "`PLAN-NOW.md` A2" or "`PLAN-NOW.md` Section H". They were left alone on
  purpose: an entry here is never rewritten, and the index those citations point
  at carries the archive pointer and the ledger, so the redirect is one hop.
  Rewriting a dozen call sites to chase a body between range files is the churn
  the stable-path rule exists to avoid.

**Closing a task is now a move, not a tick.** Plan A's 51 closed tasks left for
`docs/archive/plan-a/`, ledger row and all, so a live plan lists only live work.
Plan C is the documented exception: its Status table keeps a row per answered
question pointing at the decision, because there the row *is* the trail — only
the evidence beneath it moved.

**The cap counts LINES, and a table row has no width limit — known, accepted.**
`docs/archive/plan-a/README.md` is 118 lines and **31.7 KB**, because 51 ledger
rows are one line each and some run 300 characters; `section-j-2.md` sits at 194
lines, all but at the cap, and is 12.6 KB. *(Figures re-measured at the branch
tip on 2026-08-26 — the first draft quoted this file mid-split. An entry that had
already reached `dev` would be superseded rather than corrected; this one had
not.)* Raised in this split's own code review and declined:
a byte cap would either force the ledger to be summarised — which is the one
operation this entry forbids — or scatter it across 15 files and destroy the
single-table lookup it exists for. The cost is bounded and it is not on the hot
path: `PLAN-NOW.md` is 58 lines and 4.7 KB, and the 31.7 KB is paid only by a
reader who chose to open the closed record. **If a live file ever hits this shape, split it by
content rather than raising the cap.**

**`reference/` came in on the same pass.** `DEPLOYMENT.md` 464 → 129: the
one-time AWS setup, the IAM role, the domain and the GitHub config moved to
`reference/deployment/`, leaving the file you open during a deploy as the
deploy. `INZHUR-FUND-HISTORY.md` 280 → 109 needed no distillation at all — it
was **two `#`-level documents under one filename**, and the provider's public
read surface became `reference/INZHUR-PUBLIC-SURFACE.md`. Both were splits at a
boundary the document already had, which is the cheapest kind and the only kind
that costs a reader nothing. `MARKET-DATA-SOURCES.md` 284 → 97 went the other
way and was **tried as a distillation first, on the owner's instruction**: it
could not be done without deleting measured figures, which in a file whose whole
value is measurements is not distilling but discarding. The six source
write-ups moved to `reference/market-data/`; the summary, the closed list and
the rules it leaves us with — the part it is actually consulted for — stayed.

**Everything else came in on the same branch, and this paragraph used to say it
had not.** The first draft listed 18 files as knowingly over the cap and pointed
at a tracking table in `../README.md`; the branch then split all of them —
`docs/design-briefs/` (five), `docs/superpowers/` (three), `navigation-map.md`,
`infra/README.md`, the root `README.md` — and replaced that table with a record
of what each class cost. **Measured at the branch tip: zero Markdown files
exceed 200 lines**, and `src/docs-line-cap.test.ts` now fails the suite if one
does, so the invariant no longer depends on a sentence being re-read. The
decision log was the one that needed a decision of its own rather than a split;
that is **D96**.

**`docs/decisions/` was the one that could not simply be split — D96 resolves
it.** Its append rule
sends every new entry to the bottom of the highest-numbered file, and a 200-line
cap makes that file overflow roughly every third entry — the two rules do not
compose, and **this entry is being appended to a 1,000-line file while saying
so.** Reconciling them is a decision of its own: it has to answer what a range
file's name means when a range no longer fits, whether an entry may be split
across files, and what happens to the ~20 bare-number citations in `src/` and
`docs/`. Do not split the log on the strength of the cap alone.
