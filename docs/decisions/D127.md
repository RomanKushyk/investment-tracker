## D127 — The deadlock is accepted, not overlooked (2026-09-01)

[`D125`](D125.md) required the unit count at the JSON backup.
[`D126`](D126.md) reversed that on engineering grounds — a backup is a mirror,
not a door — after a pre-merge review traced the deadlock it creates. The owner
overruled D126. This records the ruling and, more importantly, **that it was
made with the consequence in hand.**

## What is being accepted

A store created before this branch holds pre-#31 `buy` / `reinvest` rows with no
`quantity`. Nothing can backfill them —
`w7-migration-translations.md` §4 calls those counts unrecoverable.

| the owner tries | what happens |
| --- | --- |
| Settings → Download backup | refused; the export re-reads its own output |
| Import a backup | refused; the pre-import safety backup IS that export, and `ImportDialog` returns without importing when it fails |
| Danger zone → wipe | the "Download backup first" CTA cannot produce a file |
| Fix the rows instead | **no control exists** — `useUpdateTransaction` has no caller in `src/` |

**This is not a defect report.** It was put to the owner twice, in those terms,
and reaffirmed both times. A rule the owner wants, whose price they have been
told and have paid, is a decision.

## Why the record matters more than usual here

A later session reading only the code will find an app that cannot back up the
owner's own database and will read it as a bug — the same conclusion two reviews
reached, correctly, before the ruling existed. The log is the only place that
distinguishes *nobody noticed* from *the owner chose this*.

## What D126 got right and is kept

The **export guard**. `useBackupDownload` parses what `buildBackup` produced and
refuses to offer a file that comes back rejected. It converted a silent
unrestorable file into a refusal at the moment of writing — which is how this
deadlock became visible instead of shipping — and the invariant it holds,
*never write what you cannot read*, outlives whichever rule breaks it next.

**One wording change survives the reinstatement.** The failure message no longer
names the Transactions screen as the remedy. There is no edit control there, and
a remedy that does not exist is worse than none: it now states how many rows
need counts and stops.

## The way out

A transaction-edit affordance — the ability to enter a count on a historical row.
That is a feature, not a fix, and this branch does not contain it. Until it
exists, a pre-#31 database has no backup and no restore, by design.

## Supersedes

D126 entirely: its backup-importer relaxation and its version literal.
`BACKUP_FORMAT_VERSION` returns to 4 on D122's own rule — the version tracks
what a build ACCEPTS, and this build refuses a count-less `buy`.
