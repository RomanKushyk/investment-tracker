## D128 — The deadlock is unreachable, not accepted (2026-09-01)

[`D127`](D127.md) recorded the pre-#31 backup deadlock as a cost the owner had
weighed and accepted. The owner then pointed out the premise it rests on:
**there are no live users, so there is no live data, so there is no pre-#31
database.** The state D127 accepts does not exist to be accepted.

## Every door is closed

A position-moving row can enter the store four ways, and none of them can
produce one without a count:

| door | rule |
| --- | --- |
| the seed | carries seven counts of its own (D125) |
| `transactionSchema` | requires one ([`D124`](D124.md)) |
| the S5 coupon card | asks for one when reinvest is ticked (D125) |
| the JSON importer | refuses a row without one (D125, D127) |

The one remaining source is **a database seeded before this branch** — local
state in a browser, on a project with no users, which is cleared and re-seeded
rather than migrated. That is not a data-loss scenario; it is a stale cache.

## W7 seeds fresh data too

Same premise, stated by the owner in the same breath: **W7 will seed a new demo
portfolio rather than carry the local store into Aurora.** There is no live user
and therefore nothing on the other side worth translating — the browser's
IndexedDB holds a demo portfolio and whatever was typed while building the app,
both cheaper to re-create than to migrate.

Two consequences worth writing down:

- **`transaction_quantity_required_ck` owes no backfill step.** [`D125`](D125.md)
  justified that CHECK by sequencing — backfill, then migrate. With nothing
  migrating, the constraint is simply true of everything the seed writes. The
  DDL's own comment and `user-schema.test.ts` now say that instead.
- **`w7-migration-translations.md` splits in two.** The problems that exist
  because a stored row PREDATES a rule — unrecoverable unit counts first among
  them — stop being problems. The ones about SHAPE (enum spellings, key order,
  nullability) stand: a fresh seed still has to satisfy them.

Recorded in [`../plans/phase-w-i-ii-iii.md`](../plans/phase-w-i-ii-iii.md) under
W7, which is the file a migration session is told to read.

## What goes

The export guard's missing-units counting branch and both `missingUnitsToast`
strings. They handled a state nothing can produce, which is precisely what
`CLAUDE.md`'s **"no error handling for impossible scenarios"** rules out — and
the branch had already spent two decisions and a review round arguing about how
to word a message for it.

## What stays, and why it is not the same thing

The guard itself: `useBackupDownload` parses what `buildBackup` produced and
refuses to offer a file that comes back rejected.

It is **not** handling for an impossible case — it is the invariant *never write
what you cannot read*, checked against the whole envelope rather than any one
rule. It is what turned a silent unrestorable file into a refusal at the moment
of writing, which is how this whole question became visible instead of shipping,
and it will catch whichever rule breaks the round trip next. When it fires it
now reports the parser's own first issue: the honest answer for a failure that
by construction should not have happened.

## Supersedes

D127's FRAMING — the deadlock as an accepted cost. **D127's ruling stands**: the
count is required at the backup importer, and that requirement is one of the
four reasons the state is unreachable in the first place.
