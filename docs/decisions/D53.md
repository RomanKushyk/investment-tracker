## D53 — What the xhigh review found, and the two fixes that were wrong first (2026-08-12)

**Decision:** all fifteen verified findings from the 2026-08-12 review are fixed.
Three of them changed a contract, so they are recorded here rather than only in
the diff.

### The DCF diagnostic was dated from the wrong clock

`bondQuoteCheck` was handed the **date picker's** value as the valuation date
while `fetch.feed` holds the price the provider published *now* — so recording
a missed day, the most ordinary act on that screen, made every linked bond
render "Yield looks revised". The same call also dated a **cached** payload
against today, blaming the provider for the app's own cache age.

Both are one fault: the diagnostic must date a quote from **when the payload
was fetched**. `useQuoteFetch` now exposes `feedFetchedAt` for exactly that, and
`bondQuoteCheck` takes it instead of a screen date. Verified in the browser with
the picker moved a week back: the note stays "Provider price is 6 days old",
where before the fix it became a fabricated revision warning.

### The date search preferred rounding noise over the null hypothesis

`bestValuationDate` returned the global argmin and searched only backwards, so
the ±0.05pp print rounding this module already documents dragged the fit one or
two days back — **one-directionally**, because it never looks forward. A fresh
quote at a rate rounded down was reported stale.

It now returns the **most recent** date that explains the quote within the noise
floor, and only falls back to argmin when none does. "Not stale" is the claim
that needs no evidence.

### Two fixes that were wrong on the first attempt

**Suppressing the window edge silenced the loudest signal.** Treating
`atWindowEdge` as inconclusive *before* the yield branch meant a 1.7pp revision
— far too large for the window to absorb — was reported as a benign
"out of window" note. That is worse than the bug it replaced. The edge flag now
only stops a *stale* verdict overstating its precision ("at least N days"), and
`revised` is reached as before. Its copy no longer asserts a revision either,
because the two readings genuinely cannot be separated (D52): it says the price
does not fit the published rate on any day of the window and offers the implied
figure.

**Memoising the verdicts did nothing until the dependency was stable.**
`useAssets().data ?? []` mints a fresh array every render, so the new `useMemo`
recomputed every time — the lint warning is what caught it. A module-level
`NO_ASSETS` constant fixes it. Worth remembering: a memo whose dependency is a
literal is decoration.

### The backend check could not report its own failure

`observeAndReport` caught the derivation error and logged plain text, so a
permanently failing derivation published **no datapoint at all** — an empty
series, not the flat zero the alarm rationale tells the operator to watch for.
Empty and healthy-at-zero look identical on a graph. It now emits
`observationsWritten: -1`, a value no successful run can produce.

**This is the fifth instance of the same defect** (D43, D44, D48, D49, and now a
check written specifically to prevent it). The rule that keeps failing: when
adding a signal, ask what it publishes when the thing it watches has stopped
entirely — and if the answer is "nothing", that is the same as healthy.

Separately, the manual `asOf` repair path derived from `asOf − 7` **to today**,
because `to` defaults to the current date inside `observeNbu`; a repair of a
2020 date would have walked six years forward and spiked the metric. Now bounded
at both ends.

### The rest

`useNbuRate` had drifted from its sibling `useInzhurAssets` in three places, all
of which that file documents with comments explaining why: the missing
error-guard after `refetch` (a failed fetch returned the previous success and
skipped the error toast), the missing `networkMode: 'always'` on a purely local
IndexedDB read (paused offline — exactly when the cached rate is wanted), and
the missing `gcTime` (a rate fetched minutes ago came back labelled
"not refreshed"). The display also now marks the shown rate as not-refreshed
when the last attempt **errored**, not only when nothing is cached — the toast
is gone in four seconds and the line stays on screen.

Also: the rate is requested for **Kyiv's** date, not the device's; the fetch
button no longer hides its visible text behind an `aria-label`; and
`navigation-map.md` carries the new Settings control and the new per-row note.
