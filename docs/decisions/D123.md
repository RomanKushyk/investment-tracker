## D123 — The seed never migrated (2026-09-01)

Two decisions state a fact about the seed that the seed contradicts.

| where | what it says | what `src/lib/seed.ts:18` holds |
| --- | --- | --- |
| [`D116`](D116.md) | "the seed alone shipped `'Auto (dividends)'`, now migrated to `auto_dividends`" | `reinvestPolicy: 'Auto (dividends)'` |
| [`D118`](D118.md) | "the seed's REIT holds `auto_dividends` only because the seed wrote it directly" | same |

## What actually happened

D116 migrated the value **because** it introduced a Select over stable keys with
localized labels. D118 then removed the control, BOTH renders,
`reinvestPolicyOptions`, `reinvestPolicyLabel`, `REINVEST_POLICIES` and eight
dictionary entries — and the seed migration went with them.

**Nothing in `src/` reads or writes `reinvestPolicy` any more.**
`grep -rn reinvestPolicy src/screens` returns nothing; `fixedCouponFields` never
touches the key. So the stored value is INERT, and neither `'Auto (dividends)'`
nor `auto_dividends` is better or worse for the app — the first is simply what
is there.

That is the whole correction: **the log records a migration that did not
happen.** An earlier draft of this entry argued the seed's value was actively
better because `/attributes` renders the field verbatim, which was false in the
same commit series — the render is gone. Saying "the seed is right" needed no
such argument, and reaching for one is how a correction acquires its own error.

## What a reader should take from the log

- `Asset.reinvestPolicy` holds whatever was typed, or nothing.
- **Nothing in the app reads or writes it** — that is D118's ruling and it stands.
- There is no stable key in the data. D116's key table describes a control that
  no longer exists.
- The DSQL column, the CSV column and the JSON backup member all survive, per
  D118's KEPT clause, so a real reinvestment feature has somewhere to land.

## Why this is a whole file

`RULES.md`: a decision is superseded, never corrected in place. Both entries are
accurate about everything else they say, and D118's substance — the field was
unreachable, `/portfolio`'s "auto-reinvested" is a different thing entirely —
is untouched. Only the parenthetical about what the seed holds is wrong, and a
citable log that carries a false statement about the code is worse than one
extra file. The first draft of this file proved the point by carrying one.
