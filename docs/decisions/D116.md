## D116 — The asset form asks two fewer questions (2026-08-31)

Owner's design, given in the same message that set [`D112`](D112.md)'s direction:
the new-asset form asks for things it can work out, and for one thing nobody knows
how to answer.

### Kind is derived, not asked

The Inzhur link group offered a Fund/Bond segmented control beside the ref picker.
**It never had an answer of its own.** An Inzhur bond is an OVDP, which is
`fixed_coupon`; everything else the provider lists is a fund. So the segment could
only ever agree with the yield type — or contradict it, and contradicting it
produced a picker listing the wrong instruments with no way to tell why.

```
kind = yieldType === 'fixed_coupon' ? 'bond' : 'fund'
```

This was already the segment's own default (`AssetForm.tsx` set it from `isBond`
when the link toggle went on), so the change makes a default into a binding.

**Turning the link on now adds ONE control**, the ref picker.

**The ref clears when the kind changes**, and that is the non-obvious half: a fund
slug is not an ISIN, so a yield type edited while linked leaves a ref that can only
fail to match — silently, as an unmatched asset at the next fetch. Clearing is the
honest outcome, and the picker reopens on the right list.

`KindSegment` is deleted. `TransactionPanel`'s `PriceModeSegment` was modelled on
it — but **not on its radii**, and the difference is [`D56`](D56.md)'s point.
`KindSegment` is `px-4 py-[5px] text-xs` and renders 26px, giving
round(26 × 0.26) = 7 with a track at 11. `PriceModeSegment` is `px-2.5 py-[3px]
text-[11px]` and MEASURES 22.5px, giving **6** and a track at **10**. Copying the
radii across was caught in review and corrected; a radius is never portable
between two sizes, which is why the rule is stated as arithmetic over the
*rendered* box rather than as a number.

### Reinvest policy is a list

The owner reported the field unused — "через нерозуміння як ним користуватись". A
free-text input with a placeholder and no vocabulary is unanswerable, and an
unanswerable field is worse than one that is not asked.

**Its only FUNCTIONAL role was ever truthiness.** `/allocation` tests it to append
"or pause the reinvestment" to a sell action; `/attributes` displays it. Nothing in
`src/core/` reads it. So a list costs nothing and gives the field a vocabulary.

| stored | shown |
|---|---|
| `''` | No reinvestment |
| `auto_dividends` | Automatic — dividends |
| `auto_coupons` | Automatic — coupons |
| `manual` | Manual |

**The values are stable keys and only the labels follow the language** — the value
reaches the store, the CSV export and the JSON backup, so a localized string there
would make an asset read differently after a language switch.

**"No reinvestment" is the EMPTY STRING, deliberately.** A non-empty "none" would
be truthy, and `/allocation` would offer to pause a reinvestment the asset does not
do.

### What is deliberately NOT tightened

**`Asset.reinvestPolicy` stays `string`, not a union**, and the DSQL column stays
`text` with no CHECK. The field was an open input for the app's whole life, so real
data holds real sentences — the seed alone shipped `'Auto (dividends)'`, now
migrated to `auto_dividends`. A union would make every such value unreadable by the
form meant to edit it.

A legacy value is therefore **carried as its own option**: a Select with no matching
option renders empty, which reads as "this asset has no policy" and then writes
that — destroying the value by the act of opening the form to edit something else.

### Not in this decision

**Removing `Asset.inzhur.units` from the form.** It is [`D112`](D112.md)'s fallback
and the only seed for the W7 backfill, which the owner is entering by hand. It goes
in a later change, once the ledger carries quantities.
