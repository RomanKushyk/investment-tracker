## D124 — The count is required where it is typed (2026-09-01)

[`D119`](D119.md) replaced the hand-typed coupon amount with `rate × units`.
That closed one inconsistency and opened another: the units come from the ledger
([`D112`](D112.md)), and the ledger did not have to have them.

## The reachable path

Nothing exotic — it is the default:

1. Record a `buy`. The price-mode segment opens on **total**, where the unit
   count is not needed to compute anything.
2. Leave «Одиниці» blank. It parsed.
3. `unitsByAsset` puts the asset in `incomplete`, so the count is **absent**,
   not zero.
4. `couponPerPayment` reads `held === undefined`, falls back to `couponAmount`
   — and a newly created bond has none.

The result on four surfaces, none of which says a word about it:

| screen | what the owner sees |
| --- | --- |
| `/attributes` | Купон «—» |
| `/seasonality` | the bond drops out of coupon season entirely |
| `/overview` | an `expectedPct` estimate, marked `~` |
| S5 due card | nothing prefilled |

## Why D112 was right and still wrong here

D112 declined to require a count, and gave a real reason: every row recorded
before #31 lacks one, `w7-migration-translations.md` calls those counts
unrecoverable, and refusing them would make the app unable to read its own
history.

That reason is about **stored** rows. `transactionSchema` never sees one — it
validates a row being typed, in a form, now. The protection was pointed at a
door nothing was trying to come through.

## The asymmetry, stated so nobody "fixes" it

| door | rule |
| --- | --- |
| `transactionSchema` | a moving row **must** carry a count (this decision) |
| `Transaction.quantity` | optional |
| JSON backup row | optional |
| `transaction_quantity_absent_ck` | constrains the OTHER direction only |

A CHECK requiring the count would refuse every legacy row at migration, which
is the failure D112 named. Whoever reads one of these four doors first will
find it disagreeing with another; it is deliberate.

## Details

- **Subsumes the `priceMode === 'unit'` refinement.** The panel forces `total`
  on any type that takes no units, so `unit` already implies a moving row.
- **No new message.** `quantityMissing` («Введіть кількість одиниць.») existed
  for the per-unit case and reads correctly here.
- **The seed is untouched** and still carries zero quantities across its seven
  moving rows. It does not pass through this schema, its bonds keep reporting
  their legacy `couponAmount`, and no pinned figure moves.
- Verified in real Chrome: submitting a `buy` with an amount and no count is
  refused, `aria-invalid="true"` on the field, the field message and the form
  summary both render, and no row is written.
