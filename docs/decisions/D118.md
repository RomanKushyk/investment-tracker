## D118 — Reinvest policy: the control goes (2026-08-31)

The owner's question was the right one: *«яку функцію зараз виконує селект "політика реінвестування"?»* — what does it actually do?

## What it did

| where | what |
|---|---|
| `Allocation.tsx` | **truthiness only** — appends " (or pause reinvest)" to a **sell** row of the rebalance plan |
| `Attributes.tsx` | displays the string as a Fact |

Nothing in `src/core/` read it. No derivation, no calculation, no automation. The
four values [`D116`](D116.md) had just introduced were **indistinguishable** to the
only logic that consumed it.

**`/portfolio`'s "· auto-reinvested" is not this field.** It tests
`reinvested[assetId] > 0` — actual `reinvest` transactions. The one place the app
genuinely knows about reinvestment reads the ledger, not the policy.

## Why it could not work

The control lived inside `<Reveal show={isBond}>` — the fixed-coupon group, so it
was **editable only when `yieldType === 'fixed_coupon'`**.

The Fact lived in `Attributes`' `) : (` branch — so it was **rendered only for
NON-bonds**.

Mutually exclusive. **On a bond you could set it and never see it; on a fund you
could see it and never set it.** And `fixedCouponFields()` returns the key only for
`fixed_coupon`, so a non-bond patch never wrote it either.

On the seed this is exact: `/attributes` shows `Автоматично — дивіденди` for REIT
and `—` for Energy — neither editable — while the two OVDPs have a working select
whose value renders nowhere. REIT's value exists only because `seed.ts` wrote it.

## This amends D116, and says so

D116 turned the field from free text into a dropdown because the owner could not
tell what to type. That reasoning was sound and the diagnosis was incomplete: the
problem was not the input type. **A field that is not read where it is filled cannot
be fixed by making it easier to fill.**

## What is removed, and what stays

**Removed:** the control, both renders, `REINVEST_POLICIES` /
`reinvestPolicyOptions` / `reinvestPolicyLabel`, the `/allocation` hint, and eight
dictionary entries across both languages. `optionalText` in `schemas.ts` went with
them — this was its last caller.

**Kept, deliberately:**

- `Asset.reinvestPolicy?: string` in the type;
- `reinvest_policy` in `infra/schema/user.ts` — the W7 column;
- the `reinvestPolicy` CSV column and the JSON backup member.

The seeded value survives for a reason that is now stronger than a preservation
rule: **nothing writes the key at all**, so no edit path can destroy it. It leaves
the database through the backup and the export like any other field.

## When it comes back

As a real feature, with something that reads it — the owner's own framing: fine
control over what a payout does, which is a behaviour, not a label. That feature
will want more than a policy string per asset anyway (which payouts, what threshold,
which target asset), so nothing here constrains its shape.
