## D134 — «Код» widens to 4 and derives from the ISIN (2026-09-03)

`PLAN-OPEN.md` **O27** has been open since 2026-08-24, raised by the owner while
grooming the idea list: «Код» could take 4 characters, or 6, digits as well as
letters — **or** an ОВДП could be marked some other way, by colour, by shape, or
by the last 4 digits of its ISIN. Both of the parked lines, issues
[#12](https://github.com/RomanKushyk/investment-tracker/issues/12) and
[#13](https://github.com/RomanKushyk/investment-tracker/issues/13), waited on it,
because widening a field is pointless until it is settled what the field has to
distinguish.

## The ruling

**Two halves, both the owner's, 2026-09-03.**

**1. The field.** `code` accepts **1–4 characters, letters and digits** —
`/^[\p{L}\p{Nd}]{1,4}$/u` where it was `/^\p{L}{1,2}$/u`.

**`\p{Nd}`, not `\p{N}`, and the geometry is why.** `\p{N}` also matches `No`
and `Nl` — `½`, `Ⅳ`, `٤`, the superscripts — none of which JetBrains Mono
carries. A string containing one falls back to a proportional face, and the
4 × 7,2 px premise that makes 4 fit stops holding for the string that actually
renders. "Digits" here means decimal digits.

**2. The derivation.** `deriveCode` becomes a cascade, first match wins:

| # | When | Code |
|---|---|---|
| 1 | the asset is a bond and carries a linked `ref` | the last 4 characters of `inzhur.ref` |
| 2 | otherwise, `name` carries an ISIN | the last 4 characters of that ISIN |
| 3 | otherwise | the initials of every whitespace-separated word, uppercased, **digits included**, capped at 4 — and a single-word name falls back to its first 2 letters |

*"Is a bond"* is `yieldType === 'fixed_coupon'` — the form already derives
exactly that at `AssetForm.tsx:102` and feeds it to `inzhur.kind`, so branch 1
reuses the discriminator that is there rather than inventing a second one.

**"Carries an ISIN" is not left to the implementer either.** The repo already
pins the shape, in `src/core/inzhur/ref.ts`'s docblock: *an ISIN is twelve
upper-case alphanumerics and a fund slug is lower-case kebab*. Branch 2 matches
that and nothing looser — twelve upper-case alphanumerics as a whole token — so
`OVDP UA4000238976` hits it and a name like `Fund 2024ABCD1234` does not.

```
'OVDP UA4000238976'          → 8976   (branch 2 on the seed, branch 1 once linked)
'OVDP UA4000236475'          → 6475
'Inzhur REIT'                → IR     (branch 3)
'Inzhur Energy'              → IE
'ОВДП березень 27'           → ОБ2    (branch 3, digits included)
'ОВДП травень 27'            → ОТ2
'Energy'                     → EN     (one word → first 2)
```

## The derived code is a SUGGESTION, and it never overwrites

Ruled with the formula, and it is the half that governs behaviour rather than
output. The derived value is **pasted into the Code input as a suggestion**:

- it **re-derives as the asset changes** — and "the asset" now means the name
  **and the linked ref**, because branch 1 reads the ref. `AssetForm.tsx`
  re-derives on the name field's `onChange` alone today, so that is now half a
  trigger: a bond linked after its name was typed must take its ISIN code at the
  moment the ref lands;
- it **stops the instant the user types in the Code field**, and stays stopped.
  A later name or ref change does **not** replace what the user wrote.

That gate already exists and is not new: `dirtyFields.code` guards the
`setValue` at `AssetForm.tsx:555`, and edit mode never derives at all — the
stored code stands. **What this ruling adds is that the SAME gate governs the
ref trigger.** A second `setValue` reached from the ref must carry the identical
`mode === 'create' && !dirtyFields.code` condition, or the feature that fills a
bond's code in also becomes the feature that overwrites a code the owner chose.

## Why 4, and why not 6

Measured 2026-09-03, and this is the whole of the geometry argument.
`AssetAvatar` renders a **34 px circle at `text-xs`** — 12 px — and carries no
font class, so it inherits the body face, **JetBrains Mono**, whose advance is
**0,6em ≈ 7,2 px**. Four characters measure **28,8 px** and sit inside 34 with
room; six measure **43,2 px** and do not. The only way to fit six is to widen the
circle into a pill, and a pill is the one shape [D56](D56.md) names as forbidden
outright. So **4 is an edit and 6 is a decision** — the question's own framing,
and the answer is to take the edit.

## Why the cascade, and not a mandatory link

The ISIN candidate was picked knowing it cost a second ruling: where the ISIN is
read from. **The seed settles it**: its two bonds carry **no `inzhur` key at
all** (`src/lib/seed.ts`), so the rows this whole question is about would have
been the mandatory rule's first two exceptions — a rule whose only worked
examples are exemptions from it.

**A correction to this entry's own first draft, kept because the mistake is the
reusable part.** That draft rejected the mandatory link as *circular* — "the app
has no bond discriminator outside `inzhur.kind`, so the rule cannot state its
own precondition". **That is false.** `AssetForm.tsx:102` reads

```ts
const kind: 'fund' | 'bond' = yieldType === 'fixed_coupon' ? 'bond' : 'fund';
```

and an effect pushes that derived kind INTO `inzhur.kind` (line 163). The
discriminator therefore exists, is stored — `yieldType` is an `Asset` field —
and runs in the opposite direction from the draft's claim: `inzhur.kind` is the
consequence, not the source. **So the mandatory link was rejected on cost and on
the seed, not on impossibility**, and a future ruling that wants it is not
blocked by anything this entry found.

The cascade needs none of it. It reads the ref when there is one, the name when
there is not, and nothing becomes required. Branch 2 derives `8976` and `6475`
on the seed **exactly as it stands today**.

## The collision is four assets wide, not two

The question's body recorded that both bonds are stored `code: 'GB'` and treated
that as the defect. Measured today it is half of it. `deriveCode` is
`name.trim().slice(0, 2).toUpperCase()`, so:

```
deriveCode('Inzhur REIT')       → 'IN'
deriveCode('Inzhur Energy')     → 'IN'    ← the funds collide too
deriveCode('OVDP UA4000238976') → 'OV'
deriveCode('OVDP UA4000236475') → 'OV'
```

All four seed codes — `RE`, `EN`, `GB`, `GB` — are hand-typed over a derivation
that would have produced two pairs. The owner hand-fixed the funds and did not
hand-fix the bonds, which is why only the bonds looked broken. **Branch 3 is
what repairs the funds**, and it is the reason the fallback is initials rather
than the first two letters: `slice(0, 2)` reads the first word twice whenever a
family shares a prefix, which is what both the `Inzhur …` and `ОВДП …` families
do by construction.

## What was rejected, and what merely stopped waiting

- **A square avatar for bonds** — rejected. It would have superseded
  [D56](D56.md) in writing, and it answers a different question: a square tells
  a bond from a *fund*. Two bonds stay identical under it.
- **A pickable colour** (issue #13) — **not rejected, un-parked.** It was a
  candidate only because the tint was the sole on-screen separator; the code now
  separates, so nothing depends on the colour any more. The issue stands or
  falls as an enhancement on its own merit, and its costs are unchanged and
  still real: the four palette keys are named after assets (`reit`, `energy`,
  `ovdp8976`, `ovdp6475`), they are **stored literals** — a `z.enum` in
  `core/backup/json.ts`, a CSV column, and a value on every Dexie row — so
  renaming them to colour names needs an import alias or every backup taken
  before the change fails to import.
- **The arrival-order tint stays as it is.**
  `COLOR_KEYS[existingAssetCount % COLOR_KEYS.length]` across its three call
  sites (`core/asset-builder.ts:31`, `AssetForm.tsx:735`, and
  `TransactionPanel.tsx:833`, which cycles on a different count) still encodes
  nothing about the asset and still repeats from the fifth. This ruling does not
  touch it, and does not claim to have fixed it. **The `% 4` spelling is a
  COMMENT** — `core/colors.ts:31` — **and not the code**, which O27's body had
  already corrected on 2026-08-25; this entry's own first draft quoted the
  comment back, and is fixed here so the correction does not die with the file
  that carried it.

## What this supersedes

**No decision entry.** «1–2 letters» was never a ruling — it is a comment
repeated in seven places, and every one of them moves with the code:

| Site | What it says today |
|---|---|
| `src/core/schemas.ts` | the `/^\p{L}{1,2}$/u` regex **and** its comment |
| `src/core/types.ts` | `code: string; // 2 letters shown in the avatar circle` |
| `src/core/asset-builder.ts` | `code = first 2 letters of the name, uppercased` |
| `src/components/forms/AssetForm.tsx` | `Name's first two letters only while the Code field itself is pristine` |
| `src/i18n/messages.ts` (en) | `Code is 1–2 letters.` |
| `src/i18n/messages.ts` (uk) | `Код — 1–2 літери.` |
| `README.md` §7 | `code /*2 letters*/` in the `Asset` shape |
| `src/components/forms/AssetForm.tsx:571` | **`maxLength={2}` on the input** |

**`maxLength={2}` is the site that makes the rest a no-op, and it was missing
from this entry's first draft.** Widen the regex alone and the field still
refuses a third character, while a *derived* four-character code arrives anyway
— `setValue` writes through the DOM attribute — so a bond would show `8976` in a
box the owner cannot hand-edit past `GB`. Two more two-character defaults sit in
the same block and want the same look: `placeholder="GB"` (line 569) and the
avatar's `(code || 'GB')` fallback (line 565).

**There are TWO implementations of the derivation, and only one is `deriveCode`.**
`src/core/asset-builder.ts:30` inlines the identical
`values.name.trim().slice(0, 2).toUpperCase()` rather than calling it — the
table above lists that file for its line-3 comment, which is not the same thing.
It matters beyond duplication: `NewAssetValues` (line 14) carries **no `inzhur`
and no `ref`**, so **branch 1 is structurally unreachable from the quick-create
path**. The ruling for that path is therefore branches 2 and 3 only, and
`buildNewAsset` must call `deriveCode` rather than keep its own copy — a second
implementation of a three-branch rule is a second place for it to be two
branches.

`src/core/asset-builder.test.ts` asserts the old rule by name — *derives code
from the first 2 letters of the name* — and is the test that must change first.
**README §5's avatar line is NOT on this list**, and the question's body was
wrong to put it there: that line pins the avatar's *roundness*, which this
ruling leaves exactly where D56 put it.
