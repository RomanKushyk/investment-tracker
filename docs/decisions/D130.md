## D130 — An item may cross between plans, and the row crosses without the body (2026-09-02)

`PLAN-WAITING.md` has carried this sentence since 2026-08-11: *"An item whose
date has passed moves to `PLAN-NOW.md` or is executed here directly."* Until
today every item took the second branch. **W4 is the first to take the first**,
and taking it exposed four questions the sentence never had to answer.

### 1. Where the row lands, and why first

W4's row is `PLAN-NOW.md`'s **Section Q**, above Section C. The placement is
that file's own stated order — *deadline pressure, then irreversibility, then
value per hour, then size*: W4 is the gate on W7 and on W15, and DSQL keys are
immutable, so a wrong natural key is a DROP/CREATE rather than a migration.

Section **Q** because A–P are spent and letters are cited, so none is reused.
Two columns Plan B's table does not have — Branch and Size — are **assigned at
the crossing** (`infra/inzhur-observation-schema`, M) and the row says they
were, so nobody later reads them as inherited.

### 2. The body does not move

It stays in `phase-w-i-ii-iii.md`, beside W3, and both indexes name that file.
The reason is not inertia: **W3's answered questions ARE W4's input** — the
weekend/holiday/cadence readings sit directly above the *"Then, as W4:"*
checkboxes. `../plans/README.md` already refuses to split W2 from W6 on exactly
this ground, *"splitting a measurement from the follow-up it is the baseline
for would lose what W6 measures against"*. This is that rule applied to a move
rather than to a close.

So the general form is: **the row crosses; the body crosses only if it can stand
alone.**

### 3. The row left behind is kept, and is NOT struck

**Kept**, because W7's gate, W15's gate and `PLAN-OPEN.md` O5 all cite W4 by
bare number, and an ID that resolves to nothing in the file its callers point at
is the failure the ID rules exist to prevent.

**Not struck**, and this was a code-review finding rather than a first draft:
in that table `~~…~~` means *done* — W1, W2 and W3 all carry it and all are
finished. A struck W4 saying *"the row left; the item did not close"* hands the
reader the finished-item marker on an item that is next.

### 4. A moved item closes back to the plan it came FROM

W4 archives to `../archive/plan-b/` with its body and both of its rows, never to
`plan-a/`, although Plan A's index is where it was worked.

**That is machine-checked, not a preference.** `plan.closedTasks` in
`src/facts/facts.ts` is

```ts
derived(() => countRows('docs/archive/plan-a/README.md', /^\| [A-Z]\d+ \|/))
```

and `[A-Z]\d+` **matches `W4`**. Filing a W row in Plan A's ledger would move a
fact fence that three live indexes cite, and would change its meaning from
*closed Plan A tasks* to *closed rows of any plan* — with the fence test
agreeing, because the count would be honest for the question the regex now asks.

### What is recorded but not resolved

`PLAN-NOW.md`'s header promises *"no evidence, no decision and no other phase
gates it"* of every task in the file. **W4 owes two rulings** — write-every-day
against write-on-change, and O5's non-key columns — so on the letter of that
header it does not belong there.

It is admitted anyway, with the caveat written into its own section cell,
because the two rulings are **its own first step rather than a wait on someone
else's**: O5's body has said since 2026-08-31 that *"what remains is a decision,
not a wait"*. The row therefore leads with **its first act is to ask**, and Plan
C's standing rule governs what follows — needing an answer means ask, then
record the answer as a `D<n>.md`. Re-classing O5's remainder out of *open by
design*, or rewriting `PLAN-NOW.md`'s header contract, are both larger acts than
this branch, and neither is done here.

### Why an entry and not a README bullet

The rule was first written only into `../plans/README.md`. The `/code-review`
of the branch rejected that: every comparable plan-process rule — D95, D96, D98,
D103, D105, D106, D108 — is a numbered decision, `RULES.md` requires an entry
for a contract change, and **[`D105`](D105.md) exists for precisely this reason**,
having been written down rather than left in `../plans/README.md` *"which is
rewritable"*. Without a number, `PLAN-NOW.md` can only cite the rule as *this
folder's `README.md`*, and nothing can later amend or supersede it by citation.

**Amends** D95, whose split gave each plan one index and its own section files
and assumed a row and its body never separate. They now can, in one named case.
