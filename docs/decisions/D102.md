## D102 — The decision index sheds its rules, and the cap counts authored lines (2026-08-28)

Owner's ruling, 2026-08-28, closing `PLAN-OPEN.md` **O35**.

**The problem, measured.** `docs/decisions/README.md` was two things at once: the
decision log's operating manual and a machine-written list that grows one line
per decision, at **~3.2 decisions/day since D1**. It crossed 200 lines when D99
was added, which pinned it at its own length — so every subsequent entry failed
`pnpm test` until someone ran `pnpm distillation-baseline`. Three decisions in
two days each paid that toll. A ratchet that must be bumped on every routine
operation is not a guard; it is a rehearsal for bumping ratchets without
reading them.

**Both halves of the ruling, and why neither works alone.**

**The rules move out.** [`RULES.md`](RULES.md) takes the appending rule, the
supersede rule, the front-matter contract, the generation contract and the
read-these-first list — verbatim, with only the appending bullet reworded
because this entry changes it. `README.md` keeps a title, a pointer and the
three generated tables. Its authored length is a couple of dozen lines and
**stops moving when a decision is added**, which is the whole property being
bought; the raw length keeps climbing and no longer matters. A first draft of
this entry quoted both as exact figures and was already off by one before it was
committed — the entry's own generated row had appended in between. `CLAUDE.md` pins
the index to `docs/decisions/README.md` and "that table is the one place they
are listed", and both still hold; the folder-README convention it also states
names top-level folders, which `docs/decisions/` is not.

**The cap counts authored lines.** `src/distillation/doc-line-counts.ts` gains
`authoredLines`: total lines minus everything a generator emitted between its
own markers, with the markers themselves counted because a person put them
there. A marker shown inside a fenced code block is documentation, not a live
region — `src/facts/fences.ts`'s `inCode` tells them apart, the same hardening
`src/decisions/render.ts` already needed for the same reason. Both callers ask
the new question: the ratchet in `src/docs-line-cap.test.ts` and the diagnostic
`pnpm decisions` prints.

**Exempting the file was the obvious reading and is the one this rejects.** §6's
question — does this file hold more than one purpose — is unanswerable for a
generated list, so the temptation is to skip the file. That switches the guard
off for the authored half too, and the authored half is precisely where a
second purpose can accumulate. Counting authored lines keeps the question live
on the part that can answer it, forever, however long the table gets. The order
matters as well: moving the rules out FIRST is what makes the exemption
principled rather than a hole, because it leaves a file that genuinely has one
purpose.

**This reverts D99's two-command rule.** Adding a decision is `pnpm decisions`,
once. `CLAUDE.md`, `docs/decisions/RULES.md` and `src/decisions/README.md` all
said two; all three now say one, and all three name where the rule went. D99's
own text is not rewritten — it recorded the cost honestly at the time, and O35
was filed in the same breath precisely so it would not stay.

**One sentence of D98's is corrected here, which is what `amends` is for.**
D98 justified the `docLineCounts` filter by saying `USER-FEATURES-DRAFT.md` and
`USER-BUGS-DRAFT.md` are "never staged by an agent", and
`src/distillation/doc-line-counts.ts` said "never committed by an agent". Both
are false — the owner has asked for those files to be committed, and a code
review counted three such commits, one of them the same day as this entry. The
REASONING is untouched: what a baseline run from the working tree leaks is
whatever is UNCOMMITTED at that moment, which is true of a file committed
yesterday. Only the absolute is wrong, and the live comment now says "never
committed on an agent's own initiative". D98's own prose stands; this is the
supersede.

**And a smaller thing measured in passing.** `claim-baseline.json` and
`distillation-baseline.json` are written LF by their regenerators, and without
a `.gitattributes` rule git left the working copies CRLF — so both read as
modified with an empty diff after every run. Harmless until it blocked a rebase
during this very merge. `*.md text eol=lf` already existed for the same reason
(D99's branch); the two baselines are now named too.

**What is deliberately NOT built.** A general opt-out marker. `authoredLines`
recognises one generator's delimiters, named in a constant with a comment
saying a second generator adds its opener there. A free-form
`<!--line-cap-exempt-->` would let any file leave the ratchet for any reason,
which is the hole this entry spent its argument avoiding.
